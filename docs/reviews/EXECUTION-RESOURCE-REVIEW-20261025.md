# 执行、审批与自定义资源补充走查

日期：2026-10-25。依据：用户指出尚未看到提交后的执行 / 审批管理，要求用户可配置自动执行检查、需审批等方式，并可扩展服务端环境的代码项目、MCP 和 Skill。

| 项目 | 补充交付 | 验证重点 |
| --- | --- | --- |
| 执行管理 | 独立导航、提交请求筛选、当前策略、固定上下文与资源、历次节点、交付与验收、停止合成执行 | 同一用户记录；多轮拥有者和输入版本不混淆；不增加重复运行 |
| 审批管理 | 独立待办与历史、责任人逐项审阅、通过 / 拒绝及意见、固定目标确认 | 无权角色不能批准；拒绝不执行；批准不代用户验收 |
| 用户执行策略 | 用户继承或单独配置：自动只读、逐次审批、本人确认、仅收集 | 角色与环境上限优先；自动不能放开写入或未知真实能力 |
| 资源目录 | 可新增 / 修改 / 启停 Git 项目、HTTP / stdio MCP、内联 / 仓库 / 方法包 Skill | 不含秘密、不执行模板；独立修订和依赖检查 |
| 环境绑定 | 多代码项目及 ref 覆盖、可用 MCP / Skill、环境执行策略上限 | 草稿不影响对话，发布后新计划采用新修订，旧运行快照保留 |

详细规则与 API 草案见[执行审批及资源设计](../design/EXECUTION-APPROVAL-RESOURCES.md)。本轮把资源目录与用户策略加入原有配置 / 会话链路，没有连接真实 Git 地址、Agent、MCP、模型或业务资源。

新增交互用例保存在 [execution-resource-checks.cjs](../prototype/tests/execution-resource-checks.cjs)，包括自定义三类资源、地址和依赖校验、可信启动模板、方法版本、执行策略交集、审批通过 / 拒绝、仅收集、角色限制和停止合成执行。结果及当前源码摘要见[检查报告](initial-design-checks/README.md)。

原始历史档案和 generated/v0.2 未修改。当前修订尚未推送，上一阶段 GitHub 提交及 CI 不能替代本轮本地证据。实际自动授权、资源只读限制、审批桥、服务端事务、队列并发与外部取消仍未验收。

后续按用户 UI 反馈，将审批 / 执行 / 成员 / 记录改为常规列表首屏和详情抽屉，补充[日常 UI 规格](../design/ADMIN-DAILY-UI.md)及 9 项交互检查。此前“有独立入口”不代表列表易用性已获认可；当前以新版列表和检查截图供再次评审。
