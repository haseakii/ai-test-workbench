# 整体方案复核与开发设计复审

日期：2026-10-26。范围：基于 `design/usability-refinement-20261025` 的 `a1ad45d`，复核当前设计、原型与技术可实施性。用户随后将目标更新为“再分析整体方案，完善开发文档，后端偏 Java，写完再复审并等待评审”。本轮据此交付技术提案，未开始业务实现，也不把新增提案视为已获准合并的实施基线。

## 结论

产品主线和架构职责可以保留：一个对话承载问题；系统内管理环境；管理端以列表/表单处理执行和审批；模型/ACP/MCP/代码/Skill 先配置绑定再授权使用；业务验收与后端完成分开。首批仍是一条只读报表差异链路，不因技术设计而增加用户页面或复制多 Agent 调度。

本轮发现的排队准入漏洞已在离线原型修复，合同缺项和事务说明已补齐。建议进入**技术方案评审**，不是宣称真实链路已经可用。建议技术组合为 JDK 21、Spring Boot 模块化单体、PostgreSQL、React/TypeScript 与独立 Java Runner，详见[开发设计入口](../development/README.md)。

| 级别 | 发现与依据 | 本轮处理 / 当前边界 |
| --- | --- | --- |
| P0 | 排队绑定被当成已开始执行，审批过期、相关背景改变、用户额度归零后仍生成结果；三个定向场景均复现 | 出队前重新校验计划、用途权限、额度与依赖；未发送项拒绝并提示重新准备。已开始执行保留快照；新增 3 项回归 |
| P0 | 服务文档把并发槽取得写在外部接纳之后，两个并发提交可能在回执前同时越限 | 改为分派事务内预占，先于外部发送；接纳未知保留占用。真实数据库竞争测试列为 D1 门槛 |
| P1 | 文本/原型已有用途分离和额度分级，正式类型没有 purpose、dailyTurns、总账/风险接受引用，未知用量策略只能全面阻断 | 同步声明与合成样例；增加用途、总账、指标证据和显式非硬限额例外。未知执行仍禁止另投 |
| P1 | API、状态和对象已有设计，但 Java 模块、数据库约束和崩溃窗口未形成可交付工程计划 | 新增架构/代码层级、逻辑表、锁/事务、outbox/inbox 与错误恢复设计；无业务代码落地 |
| P1 | 准备计划可能被误读为已经允许读取全部代码和业务数据 | 明确准备只用获权配置/材料；新取证须另有只读授权；说明上下文不是资源授权 |

| P1 | 当前评审单仍有较早的“企业身份先行”建议，易覆盖后续按风险开通的决定 | 更新当前建议为选定一种成熟身份源，内部测试/敏感环境分级；不增加双账号体系前置要求 |

## 写完开发文档后的第二次复审

按下列真实操作与失败场景重新对照文档、类型和原型，不是额外的真实服务验收。

| 场景 | 复审结果与对应设计 |
| --- | --- |
| 新成员登录后提交问题 | 身份验证、成员开通和环境授权分开；无理解外发授权只能收集；[API](../development/INTEGRATION-AND-API.md) 不允许客户端自报角色 |
| 管理员配置系统与能力 | 运行档案→Agent→模型→资源→系统内环境→成员求交集；保存、发现、核准、发布和绑定独立；不新增日常菜单 |
| GitLab Token 与本地目录 | Token 留秘密服务，代码固定为 commit/内容快照；本地目录属于执行节点；说明与真实代码证据分开 |
| 用户自动执行或需要审批 | 自动授权仍绑定操作；无本人审批权转负责人；批了但没出队要重查；进入真实执行后只按原拥有者核查 |
| 两个会话同时申请额度 | 总账/分项/并发与 outbox 同事务预占；未接纳不等于没占用，旧周期未知不归零；[事务](../development/DATA-AND-TRANSACTIONS.md) 明确锁和唯一键 |
| 长时间等审批、页面关闭 | 后台持久等待，前端断开不取消；原生请求过期需要新请求和决定；不循环调模型或自动重新 prompt |
| 服务崩溃或停止与完成竞争 | 接纳日志、稳定命令键和外部权威回执收敛；普通 not_found、租约到期和 cancel_requested 不释放未知占用 |
| 上下文和记忆撤权 | 先 ACL 后检索；摘要保留来源；不能恢复含撤权材料的 Agent session；长期记忆默认关闭 |
| 结果文件与用户确认 | 确定性计算、版本/时点/完整性检查；文件 ready 才下载；用户确认绑定结果修订；后台同一 conversationId 标题 |
| 管理员排查 | 任务/审批列表只显示获权元数据；正文租约和文件下载独立授权；关联命令、Binding、工具、证据和用户验证 |
| 工程规模 | 三个 Maven 模块、一个业务库、一个执行节点；无消息中间件/微服务/新编排引擎前置要求；[目录规划](../development/ARCHITECTURE-AND-CODE.md) 不等于已生成工程 |

复审又统一了三处表述：合成 accepted 样例应假设相应强制能力满足，不能同时携带“未知能力而要求硬限额”；非硬限额下的未知用量例外不应被错误表一概否定。示例 verified 仅是合同假设，真实 Provider 仍全部 not_run。并发预占与状态转换也分别对应 T_DISPATCH 和 B01/T_SEND：先占槽/写 outbox，再由适配器登记 sending，避免技术表格提前改变 Binding 状态。
