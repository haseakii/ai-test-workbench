# 整体设计与原型走查

日期：2026-10-25。范围：从用户提问到管理员排查的设计及离线原型。未启动真实模型、Agent、MCP 或业务资源。

## 发现与修补

| 编号 | 走查发现 | 本轮完善 | 证据 |
| --- | --- | --- | --- |
| W01 | 用户对话与管理记录是独立样例，缺少一条可追踪的共同记录 | 新增同页合成记录，关联用户、事件、上下文、Binding、结果、下载与验收 | [衔接合同](../design/END-TO-END-WALKTHROUGH.md)；[journey.js](../prototype/journey.js)；walkthrough administrator 用例 |
| W02 | 模型选择变化仍能使用旧待确认卡片；快照修订与当前校验修订混用 | 模型 / 输入 / 授权 / 记忆 / 工具观察变更使计划失效，分别保存冻结配置与当前准入修订 | walkthrough model / MCP observation 用例 |
| W03 | 提交人的“允许”没有区分具体审批权 | 本人只读审批能力单独配置，无权者送负责人；负责人只批准固定计划，不代验收 | walkthrough submitter 用例 |
| W04 | 对话结果缺少文件交付及结果轮次约束 | 合成 CSV、按需来源说明、结果 / 输入版本确认、下载重鉴权 | walkthrough file / result / download 用例 |
| W05 | 用户暂停和权限变更仅发生在管理样例，未传递到当前对话；历史标题过滤不充分 | 当前预览用户映射到管理用户，撤权禁发并隐藏不可访问标题，保留草稿，恢复不复活旧批准 | walkthrough pausing / restoring 用例 |
| W06 | 记忆状态与本轮材料脱节；来源撤权未传播到派生结果和审阅缓存 | 只采用审核且来源仍有效的记忆，依赖修订入上下文；撤权隐藏派生正文、禁下载 / 验收并撤销审阅租约 | walkthrough memory / source revocation 用例 |
| W07 | 正文审阅仅有手动过期，离开后可能沿用旧授权 | 自动到期、角色 / 授权变化与离页清理，审阅理由按记录保留，不被事件刷新覆盖 | walkthrough automatic expiry / leaving review 用例 |
| W08 | 对话中的待确认卡片没有自动到期路径 | 明确计划有效期并自动失效，迟到确认不得创建执行 | walkthrough expired pending plan 用例 |

## 验证边界

本轮新增完整链路用例，和已有对话、四项配置、接入治理、合同状态恢复一起执行。当前数量、源码摘要及失败 / 通过情况以[检查报告](initial-design-checks/README.md)为准。此前 64 项通过是上一阶段记录，不能当作本轮新增链路的验证。

旧版文本档案和 generated/v0.2 不改动。五层正式状态转换及 ExecutionProvider 单一拥有者原则继续适用；共享离线记录没有替代这些合同。生产事务、外部取消、权限强制、模型能力、工具副作用与真实证据仍待实施后验收。

已复查用户交付与本次管理员记录截图，修正了事件序号重复及主要按钮悬停对比度。最终交互检查为 81/81，包含 17 项整条链路走查；68 个视口组合无整页横向溢出。
