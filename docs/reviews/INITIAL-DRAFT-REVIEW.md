## 先确认产品是否合用

产品服务于测试人员的日常排查：选系统和环境 → 描述问题 → 补条件 → 按规则授权 → 看依据和文件 → 确认解决或继续排查。用户端保持一个连续对话，范围、进度和结果按需打开。管理员用任务、审批、成员列表处理日常事务，在系统设置下维护环境、背景和能力，在成员设置下维护模型额度。

参考历史原型的工作区、列表和表单；没有要求首版实现历史全部页面。固定检查流程用于限制本次能够使用的方法和资源，自由流程画布、知识库全面建设、受控写入和多 Agent 调度不作为首条闭环前提。诊断演练只帮助评审，不属于测试人员日常导航。

模型理解问题并提出检查计划，平台决定可用范围及审批责任，执行后端负责受委派执行，受控资源服务落实真正的访问限制。任何一层都不能以“模型说可以”替代另一层的授权或事实。

## 建议按这条顺序看原型

直接打开[当前原型](../prototype/index.html)。所有操作都是固定合成身份和内存样例，刷新会清空；不输入真实客户材料或账号秘密。

| 顺序 | 操作入口 | 重点判断 |
| --- | --- | --- |
| 1 | [对话](../prototype/index.html#chat)：选系统环境，提出报表与明细差异，补时间和状态 | 是否能直接开始，状态和下一步是否清楚；自动标题是否合适，顶部重命名是否方便 |
| 2 | 对话内确认范围，查看示例结果和“问题信息”，下载合成差异，确认或继续 | 授权是否可理解；结果依据是否好找；用户验收是否与执行完成分开 |
| 3 | [审批中心](../prototype/index.html#admin-approvals)、[任务中心](../prototype/index.html#admin-executions) | 列表能否快速找到待办；点开再看具体条件和动作；样例预览是否与本次对话明确区分 |
| 4 | [系统设置中的环境](../prototype/index.html#admin-systems)、[检查流程](../prototype/index.html#admin-workflows)、[资源目录](../prototype/index.html#admin-resources) | 环境关联代码项目 / MCP / Skill，流程限定依赖；草稿不会提前影响用户 |
| 5 | [成员](../prototype/index.html#admin-users)：编辑当前对话用户的范围和执行方式，返回对话 | 自动只读、本人确认、负责人审批、仅收集是否适合日常管理；撤权后能否明确说明原因 |
| 6 | 刷新后打开[首次开通演练](../prototype/index.html#getting-started) | 新用户申请后无环境权限；管理员选范围并开通，再进入同一对话链路 |
| 7 | [用户记录](../prototype/index.html#admin-records)：选择同一问题，使用支持审阅员演示身份并填写用途 | 管理员能否找到执行与结果；正文读取和普通配置权限是否分开 |

补充接入管理走查：从 [Agent 与模型接入](../prototype/index.html#admin-integrations) 新建连接并模拟发现，直接创建模型预设，再去系统环境和成员权限显式绑定。依次检查 [运行配置](../prototype/index.html#admin-runtime)、[上下文策略与记忆](../prototype/index.html#admin-context)，最后核对记录中的同一执行快照。

演示身份选择器仅供评审操作不同职责，不构成登录或权限服务。真实产品由服务端解析身份，不让用户用选择器获得角色。

## 初稿建议，供统一批准或调整

| 决策 | 建议 |
| --- | --- |
| 首版范围 | 一个团队、一个系统和测试环境、一个报表核对场景；连续对话加列表管理；先完成真实只读闭环 |
| 开通方式 | 选定一种成熟身份方式，优先复用已有企业身份；无身份源的内部测试可评审邀请制本地账号，未开通零环境权限；按风险指定责任人，不同时建设两套账号体系 |
| 执行权限 | 新成员默认本人确认或负责人审批；自动只读按用户和环境显式授权；写入和生产访问留待另行评审 |
| 初始记忆 | 保存持续会话；跨会话长期记忆默认关闭，有来源和责任人再开放 |
| 下一阶段工作 | 明确授权后实现最小服务和受控适配；先用合成夹具验证真实服务，再接获授权测试资源；无需先完成所有管理页面 |
| 验收责任 | 指定试点系统负责人、审批责任人、结果验收人及部署负责人；真实验收按[完整场景门槛](../design/FIRST-USE-AND-TRIAL.md)逐项留下证据 |

进入真实阶段还需要用户指定：部署位置和访问方式、可用身份源、试点后端 / Agent、模型账户及可用预算、一个系统环境和允许读取的资源范围。凭据通过受控秘密配置提供，不粘贴到设计稿、聊天示例或公开仓库。保留期、备份恢复目标、内容审阅责任可在首次环境配置评审时一起确定。

目前没有开展业务开发或部署，因为用户此前明确“仍然只做设计和原型”，并要求最后统一审批。需要确认的是上述具体初稿和下一阶段范围，而不是把架构认可视为真实接入的自动授权。未获下一阶段授权前，保持当前可审阅材料，不以不断增加页面代替实机证据，也不把完整目标标记为完成。

标题补充：自动概括、一次细化、手动接管和前后台一致性已纳入[交互规格](../design/INTERACTION-SPEC.md#任务自动命名与手动重命名)，仍以本地规则模拟，未调用真实模型。

本轮按用户要求补系统内环境、项目 / 环境背景进入执行、全局默认和成员 Agent / 模型额度。完整规则见[系统上下文与额度](../design/SYSTEM-CONTEXT-QUOTAS.md)，仍不包含真实计量、资源调用或服务实现。

接入与治理入口已按[完整操作路径](../design/ACCESS-GOVERNANCE.md)收敛：连接 / 模型、运行、上下文、成员和记录逐一设计；MCP 与系统环境绑定独立明确。新增仅离线配置与合成关联，不构成真实接入可行性证明。

## 本次连续走查与下一阶段审批范围

新增连续用例通过页面新建运行配置、ACP Agent、模型、上下文、代码项目、MCP 与 Skill，绑定到现有订单测试环境和固定流程，再完成成员申请、权限开通、对话、审批中心决定、文件下载、用户确认及记录审阅。配置到审阅之间没有刷新、重置或直接注入业务状态。跨页引用见[链路记录](initial-design-checks/complete-journey.json)，合成差额可由[CSV](initial-design-checks/complete-journey-difference.csv)复算。目录、系统、身份和回复仍有预置样例，不能据此称空部署或真实执行完成。

下一步如获批准，建议先做**本项目、本机隔离、合成数据的服务验证**。这是一项新的实施授权，尚未开始。具体交付如下：

1. 可重复的本地启动、停止和重置说明；仅监听回环地址；独立数据目录，不修改其他项目。
2. 配置、成员、会话、审批和结果由真实服务持久化；重启后记录保留，前端不能自授角色或直接改变权威状态。合成身份仅限测试模式，不能称真实 SSO。
3. Provider 测试替身验证幂等提交、接纳未知、取消、事件恢复和审批过期；明确显示其为夹具，不能称 ACP / 总控适配完成。
4. 从页面完成同一完整链路，服务端逐项检查环境、工具、额度和产物访问；记录拒绝路径、并发提交及崩溃恢复证据。
5. 提交真实 Agent 接入差距与试点清单。两种实际后端、真实身份、获授权资源及部署验收仍必须随后完成，不以本地夹具代替完整目标。

该批准范围不包含付费模型、真实 Token、业务数据库、外部部署、改动总控或公开上传新增材料。进入这些操作时再按指定目的地、账户、预算和资源范围执行授权。身份源、试点系统、负责人、运行主机和实际后端可集中在真实试点前确定；不能在缺少这些输入时伪造验收结果。
