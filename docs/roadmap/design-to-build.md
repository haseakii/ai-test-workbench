# 从设计到开发的实施门槛

本页是待排期计划，不代表已开始编码或获得业务资源授权。

## M0 · 完成设计评审与独立仓库归档

保留 v0.2 原稿与架构提案，记录已认可方向。当前[初始设计与原型](../design/README.md)已补齐平台管理、执行连接、固定绑定与审批恢复的评审草案，不另分产品版本。用户逐项评审仍未完成。

## M1 · 冻结最小执行契约

正式合同草案与五层转换表已形成，见 design/。当前内存模拟检查部分关键约束，尚未实现假 Provider 或完成后端共同契约测试。下一步评审合同，再另行授权工程实现；模拟不算真实执行验收。

## M2 · 总控适配器真实只读闭环

接入一个获授权系统和测试环境，完成文字/截图/表格输入、补充条件、匹配部署代码、只读取证、结果文件和用户验证。补齐原生审批桥接与二进制文件传输缺口，不冒充已有能力。

## M3 · ACP 直连独立验收

总控服务停止时，由薄 ACP Host 完成同类基础排查，仍受相同资源授权和预算约束。处理能力协商、实际模型确认、权限请求、停止和会话恢复差异，不建设第二套 Boss。

## M4 · 受控变更与复杂协作

测试环境数据变更和代码修复分别验收，包含固定计划审批、前置状态复查、结果核验和结果未知处置；复杂多 Agent 协作通过总控。生产写入另行接入与授权。

## 所有阶段的门槛

用户和环境隔离、附件和产物授权；版本和模型配置可追溯；幂等和单一执行拥有者；外部副作用未知不重放；已知/估算/未知消耗分别记账；无凭据提交；测试失败与未覆盖项如实保留。

## 对话与管理配置边界

用户端采用已认可的单一对话形式；后台先完成系统、环境、模型、权限的配置评审和离线联动，见[管理设计](../design/ADMIN-CONFIGURATION.md)。后续实施需补真实配置发布事务、身份与逐项 ACL、能力发现、资源映射及撤权在途行为；本轮模拟通过不解除这些门槛。

完整前后台设计已扩充[需求覆盖](../design/DESIGN-COVERAGE.md)，当前退出条件是设计及离线交互可审阅。后续须单独授权实施，再验证模型认证、协议协商、资源隔离、事务与事件恢复、内容访问租约、记忆删除和总控关闭下的 ACP 链路。

用户提交后的执行 / 审批工作台和可扩展环境资源已加入[设计](../design/EXECUTION-APPROVAL-RESOURCES.md)。未来实现需将用户策略、自动授权凭据、角色和环境上限、资源目录修订、准入检查、事务与审计落实到服务端，不能直接将离线勾选或状态作为权限。

## 从空部署到第一次使用

后续真实试验按[首次开通与完整场景](../design/FIRST-USE-AND-TRIAL.md)执行，补部署、一次性引导、注册申请、权限授予及重启恢复证据。现有离线检查只能说明页面和合成状态联动；阶段目标仍包括总控与 ACP 两条实际执行路径，不能以页面检查代替。实施与资源访问等集中交用户统一审批。
