# ADR-001：独立业务平台与可插拔执行后端

**状态：架构方向已认可；实现细节仍需技术评审。**

## 背景

测试协作平台需要管理业务问题、用户权限、审批、预算、证据和验收；通用总控则管理被委派的 Agent 任务及其内部执行。将两者合并会让业务规则侵入通用执行引擎，也会把平台绑定到总控的内部存储和生命周期。

## 决策

建设独立业务平台，通过稳定的 ExecutionProvider 契约接入不同执行后端：

- **总控适配器**：将业务节点委派给 multi-agent-control-plane，保留总控内部的任务树、协作和执行尝试。
- **ACP 直连宿主**：提供受控 ACP Client、单 Agent 进程与会话管理，支持基础流程不依赖总控运行。
- **资源服务**：统一约束代码、数据库、日志、MCP 和文件访问；不能仅靠提示词限制 Agent。
- **业务平台**：拥有用户、系统环境、业务流程、审批责任、预算、证据、结果版本和用户验收。

## 必须保持的边界

1. 不 fork 总控，不共享或直接读写总控数据库，不复制完整多 Agent 调度引擎。
2. 同一个执行单元只能有一个执行拥有者；运行中固定后端绑定。
3. 外部执行结果未知时先按原键核查，不静默换后端或重放。
4. 两条执行路径使用一致的身份、资源授权、审批和额度规则。
5. Agent 完成事件与业务问题解决状态分开。

## 验收标准

先验证一条经授权的只读排查走总控路径，再关闭总控验证 ACP 直连的基础流程。两个后端都要通过同一套执行契约测试；仅有接口或离线模拟不能算接入通过。

技术栈、平台数据库和执行宿主的实施提案见 [ADR-002](ADR-002.md)。当前仍处于设计阶段，没有真实后端或资源接入。
