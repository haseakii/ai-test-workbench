# ADR-002：Java 业务单体与独立受控执行宿主

**状态：proposed，等待用户评审。日期：2026-10-26。**

用户偏好 Java 后端，现有产品需要在审批、预算、执行绑定与事件之间保持明确事务边界。建议以 JDK 21 / Spring Boot 构建模块化业务单体，PostgreSQL 保存独立业务状态和事务 outbox；ACP 使用独立 Java Runner 承载受限 Agent 进程。平台仍通过同一 ExecutionProvider 接入外部总控，原有职责归属不变。

不采用全 Node 业务服务是维护偏好的取舍；不把每个模块拆成微服务，是为了避免首条闭环提前承担分布式事务与多组件运维。选择显式 JDBC/SQL 而非默认 ORM 聚合，便于审阅幂等、锁和额度预占；选择 PostgreSQL 单一数据库目标，暂不承担多数据库兼容成本。

代价是需要编写 SQL、迁移及 Runner 接纳日志，并验证 Java 协议库的实际兼容性。SDK 只减少协议工作，不提供业务审批、安全隔离或恰好执行一次。首次真实接入前按实际后端和协议版本验收；若必须增加薄协议桥，另记取舍，不扩张成第二套总控。

详细候选版本、目录与验收见[开发设计](../development/README.md)。此提案未冻结依赖、没有创建服务工程，也不授予真实资源访问或部署权限。当前 ADR-001 继续有效。
