# 执行管理、审批策略与可扩展环境资源

初始设计评审稿。本轮按用户要求把提交后的执行管理、审批管理做成明确入口，并把代码项目、MCP 与 Skill 从固定摘要改成可维护目录。仍只交付设计和离线原型。

## 管理端入口

主导航增加“执行管理”“审批管理”，与“用户记录”分开：执行页关注用户提交和历次节点执行；审批页关注具体计划的待办与决定；用户记录关注有用途授权的正文审阅。原有“审批恢复演练”继续是协议与状态评审入口，不能代替业务审批工作台。

| 入口 | 展示与筛选 | 允许动作 | 禁止的隐式行为 |
| --- | --- | --- | --- |
| 执行管理 | 用户 / 问题 / 范围、当前请求状态、输入修订、有效执行方式及原因、Binding、资源快照、历次节点运行、结果与验收 | 获权执行管理员请求停止；跳转同一用户记录 | 不能因为超时直接换后端重跑，不把提交视为已启动 |
| 审批管理 | 待我处理 / 全部审计、申请人、责任范围、固定计划、输入 / 上下文 / 资源修订、有效期、意见与历史 | 有权责任人逐条批准或拒绝，拒绝须理由；冲突重新审阅 | 不批量批准未审参数，不替用户验收，不把批准当执行完成 |
| 用户与权限 | 角色、环境范围、每个用户的执行方式、变更理由及授权修订 | 预览影响后保存；暂停 / 恢复 | 不允许聊天提示词、普通用户或管理范围外人员提高自动执行权限 |
| 环境配置 | 默认模型、执行策略上限、代码项目 / ref、MCP、Skill | 从目录选择并发布一份固定配置 | 不允许资源绑定自动扩展到其他用户、环境或在途运行 |
| 资源目录 | 代码项目、MCP 服务、Skill 方法，可新增、编辑、启停 | 保存草稿、校验依赖、预览并应用到离线配置 | 不因点击启用就拉取代码、连接 MCP 或执行 Skill |

执行管理按问题聚合当前提交，并可查看每次 NodeRun / Binding；正式服务还应支持按独立运行分页检索。原型保留各轮合成执行 ID、输入版本、拥有者、状态及结果版本。首次消息、补充条件、等待审批、创建执行、产物就绪、用户确认分别是不同事实。

日常页面采用完整列表和按需详情抽屉，详见[日常管理 UI](ADMIN-DAILY-UI.md)。审批历史以具体计划分行，示例数据与当前提交隔离；技术引用与审计不占据列表首屏。

## 执行方式

| 模式 | 行为 | 授权及审计 |
| --- | --- | --- |
| 自动只读检查 | 条件齐备且命中已批准的只读范围后，可不再逐次打断用户 | 每次具体动作记录策略 ID / revision、签发者、范围匹配和限额消费；不是无授权 |
| 每次负责人审批 | 条件齐备后自动进入审批待办，提交人不能绕过 | 固定操作、参数、环境、前置条件、材料与有效期；批准与拒绝均审计；准备标识不表示已向后端提交 |
| 本人确认 | 用户有此本人会话只读审批权时确认，否则送责任人 | 不能用本人确认去批准他人、写入或范围外动作 |
| 仅收集问题 | 保存问题与材料、补条件，不创建 Agent 执行或审批动作 | 只记录业务输入；正式产品不为此调用执行模型 |

角色提供默认模式和“允许获配自动只读”的上限；用户可继承或由获权管理员单独指定模式。环境再施加上限：允许受限自动只读、必须负责人审批或仅收集。最终模式由服务端求交集，不由前端值或 Agent 自述决定。

判定顺序：用户暂停 / 身份或范围失效 → 阻断；任一约束仅收集 → 仅收集；动作涉及禁止写入、危险能力或无法限定参数 → 阻断；用户或环境要求逐次审批 → 审批；请求自动但角色未允许、资源或已批准模板不匹配 → 审批或拒绝；其余按获准自动 / 本人确认处理。真实能力、认证、资源身份、隔离和预算准入是额外硬门槛，不能因自动模式放行 unknown。

原型的自动只读只推进本地定时模拟，实际模型和工具仍为 unknown / not_run。策略命中记录为 policy authority，不伪造成一次人工批准。仅收集不新增 Binding；可执行计划可先分配 prepared Binding 标识，但每次审批只在责任人明确决定后提交执行并激活拥有者；所有模式都继续保留用户验收。

## 自动授权合同

AutoExecutionGrant 至少绑定 subject / tenant、角色与授权修订、系统环境、允许操作模板、项目 / 路径、MCP 工具与 schema、Skill 哈希、参数及数据范围、输出类型、调用次数 / 并发 / 费用风险、有效期及签发责任人。每次动作匹配后产生针对 operationHash 的独立授权决定；不能把一次政策批准转成任意工具的 allow_always。

决策来源有 human 和 policy 两种。policy 决定包含自动授权引用、配置修订、匹配证据及执行服务身份；人工策略签发人不伪装成本次点按钮的人。权限桥只在当前原生请求、批准范围、计划和期限完全匹配时响应 allow_once；资源服务执行前仍独立复查。内层拒绝优先于外层自动 / 人工决定。

切换用户模式、收紧环境策略、撤权、资源修订或策略到期，使待执行计划重新判定；不能把已拒绝计划静默变成自动执行。恢复用户不恢复旧批准。已发出的真实动作仍按取消及核查合同处理，未知结果保留拥有者和预算挂账；不因为策略变严便声称动作未发生。

## 可扩展资源目录

| 对象 | 必需字段 | 扩展与约束 |
| --- | --- | --- |
| CodeProject | 稳定 ID、显示名、来源类型、Git 地址 / 本地节点目录、Git 默认 ref、允许路径、认证引用、责任人、revision、启用 | 支持多个项目；Git 使用 HTTPS 或受控 SSH，本地使用授权节点目录；固定 commit 或文件快照，禁止嵌入秘密 |
| McpDefinition | ID、名称、HTTP 端点或受信 stdio 模板、协议与认证引用、工具允许集、schema 观察、风险、系统范围、revision | MCP 目录和环境工具授权分开；新增工具 / schema 变化重新审核；声明 readOnly 不等于已验证 |
| SkillDefinition | ID、名称、来源类型 / 引用、版本、内容或说明、内容哈希、所需 MCP / 工具、输入输出合同、revision、审核状态 | 可来自受控项目文件、方法包或内联；不执行安装 hook 或任意脚本；Skill 不授予资源权限 |
| EnvironmentResources | environmentId、项目列表及每项目 ref 覆盖、MCP 列表、Skill 列表、执行策略上限、依赖修订 | Skill 所需 MCP 必须已被环境允许；资源本身和用户都获权后才能进入计划 |

代码地址与认证引用分别管理，不允许 URI 中放密码、Token 或下载签名；stdio 只选受信启动模板，不能把用户文本当 shell 命令。Skill 资源先由受控导入流程读取 / 审核 / 固定哈希，运行中只消费已准入版本；不能因为 Skill 指向某个仓库而自动授予该仓库源码读取权。

新增目录项默认停用，环境不自动关联新项，既有用户也不自动获得资源权限。每次编辑创建新 revision；禁用前检查环境和 Skill 依赖，允许在同一发布中调整引用。用于历史审计的旧版本保留；真实资源撤权仍优先于保留快照。

目录可按受控 schema 增加资源类型和字段，使用 `kind + schemaVersion + validatedConfigRef` 的注册接口；未知类型 / 字段不能自动下发给 Agent。扩展依然需要服务端类型校验、适配器、权限策略、审计和实际能力验收，不能把任意 JSON / URL 当通用可执行插件。

## 环境与计划冻结

草稿编辑 → 依赖 / 地址 / 角色检查 → 影响预览 → CAS 发布配置 → 后续计划解析引用。目录修订与环境绑定同批保存审计；真实接入准入仍独立。新环境可以暂时不绑定资源，但明确未配置，不得因此真实执行。

对话固定系统和环境；每个执行单元准备时从当前已应用环境解析资源目录，保存 resourceConfigurationRevision、项目地址引用与请求 ref / 实际 commit、MCP revision / schemaHash、Skill revision / verifiedContentHash，以及执行方式判定与 policyRef。实际 commit / schema / 内容未知，保持未知并阻断需要它们的真实操作。

资源变化后新计划可采用新修订，旧待执行计划失效；已运行 Binding 的快照不被编辑。一个问题的多次执行各有 NodeRun / Binding，队列聚合不丢失旧运行。仅修改“默认”不能让原拥有者或重试切到另一套资源。

## API 与事务草案

| 入口 | 输入 / 输出 | 关键守卫 |
| --- | --- | --- |
| GET /admin/executions | 用户、范围、业务状态、cursor → 获权的提交及运行 | 先范围过滤；正文 / 附件另鉴权 |
| GET /admin/approvals | responsibility、state、cursor → 待办及决定历史 | 责任人资格、范围与租户过滤 |
| POST /admin/approvals/{id}/decision | 决定、operationHash、expectedRevision、理由 | 单条 CAS；当前计划未失效；同键只记一次 |
| PATCH /admin/users/{id}/execution-policy | 基础授权修订、模式、可选授权范围 / 期限、理由 | 可授予范围、角色 / 环境上限，敏感自动授权需独立复核 |
| POST /admin/resource-definitions | kind、受控 schema、元数据、sourceRef → 草稿 | 不接受原始秘密；未知类型拒绝 |
| PATCH /admin/resource-definitions/{id} | expectedRevision、变更 → 新资源修订 | 依赖检查、发布审计；不修改历史运行快照 |
| PATCH /admin/environments/{id}/resources | expectedRevision、project/ref / MCP / Skill 引用、策略上限 | 资源与依赖存在、当前有权、配置快照原子发布 |

自动授权决定、预算预占、唯一节点 / Binding 与 outbox 必须一致写入；人工决定与原生送达 / 动作结果继续分层。拒绝后保持不执行，补充或重开产生新计划，不复活旧批准；审批过期不等同执行失败。正式执行状态仍以 Provider 权威事实为准。

## GitLab Access Token 配置

用户明确日常使用 GitLab，代码目录新增在线 Git / 本地目录选择。在线 Git 默认展示 GitLab，可选其他 Git；认证方式包括无需认证、Access Token（HTTPS）、SSH 密钥引用和已有受控凭据引用。私有 GitLab 仓库可直接录入 Access Token，不要求用户先手写秘密存储引用。正式保存后只返回“已配置”、凭据引用 / 修订、更新时间和可用性观察，原值不回显；更新必须输入新值，清除需明确操作。

Token 类型可选 Personal / Project / Group Access Token 或 Deploy Token。HTTPS 用户名独立于 Token：PAT 使用非空用户名；Deploy Token 使用创建时分配的用户名。只读 Git 拉取按支持的令牌类型选择 read_repository 等相应只读范围，不为了方便要求 api 或 write_repository。私有实例的版本、可用令牌类型、有效期及组织策略需在真实接入时核查。依据：2026-10-25 只读查看 [GitLab PAT 文档](https://docs.gitlab.com/user/profile/personal_access_tokens/)、[Deploy Token 文档](https://docs.gitlab.com/user/project/deploy_tokens/)、[令牌范围](https://docs.gitlab.com/security/tokens/access_token_scopes/)。不把这些公开说明当作用户实例已验证。

真实服务的秘密写入接口与普通配置发布分开：获权管理员通过受保护的服务端通道提交令牌，凭据库加密保存并生成项目 / 目标主机限定的不可逆展示引用；普通配置、审计、URL、命令行参数、仓库配置、浏览器存储、上下文清单、异常和导出均不含令牌值。浏览器输入框是 password、不可回填；服务端禁止请求体日志和异常回显。读取源码不代表当前用户获得 Token 的读取权，也不因一个 PAT 能访问多个仓库就扩展项目权限。

保存凭据不等于认证成功。连接检查分别记录可达、认证、仓库读取、ref 解析、路径限制和观察有效期；错误只显示脱敏原因（地址 / 凭据失效 / 无项目权限 / ref 不存在 / 范围不符），不自动降级到其他账号、分支或本地目录。令牌过期或撤销后禁止新拉取，按策略复查已缓存快照能否继续使用；更换凭据引用 / 修订使尚未执行的计划重新准备，在途执行仍由原拥有者核查。

**离线原型不会保存令牌。** 输入框仅供填写虚构演示值，“模拟保存 / 替换 Token”立即清空输入并生成合成引用；值不进入配置草稿、发布快照、审计或会话。未模拟保存的值在应用配置前清空并提示；切换表单不保留输入。清除引用与应用配置的步骤独立，不冒充真实 Token 已撤销。正式令牌录入、加密存储、探测和撤销均尚未实现。

本地目录的节点归属、快照和安全边界见[运行资源](RUNTIME-RESOURCES.md#代码项目来源本地目录与在线-git)。本地项目不显示 Git 分支和 Token 字段；环境页对其显示节点与文件快照说明，只有 Git 项目支持环境级 ref 覆盖。
