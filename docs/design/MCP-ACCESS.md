# MCP 接入与工具治理

初始设计评审稿。MCP 用于工具/资源接入，ACP 用于 Agent 执行会话，模型账号用于推理访问；三个对象不能混成一个“模型连接”。

## 连接与准入

McpConnection 保存 ID、责任人、transport、协议版本、受信服务/制品引用、endpointRef 或 stdio 启动模板、authRef、执行身份模式、数据出口、能力观察及期限、允许系统环境、工具注册表、参数 schemaHash、风险分级、超时/响应大小/调用预算和禁用状态。

准入步骤：配置草稿 → 协议/认证发现 → 工具/资源清单观察 → 人工核准工具及参数 → 在隔离测试区验证资源限制 → 可用。连通、tools/list 成功或工具自称 readOnly 均不足以通过准入。新增工具或 schema 改变进入待审核；旧运行固定旧清单，不能自动获得新工具。

## 协议版本与传输

连接必须保存协商版本，不使用未标版本的“最新 MCP”。2026-07-28 与 2025-11-25 的 Streamable HTTP 行为不同，前者移除了旧 GET 流及协议会话；兼容端需按实际版本处理。不能把老会话 ID、恢复游标规则直接套给新版本。当前只读官方核查见[协议观察](PROTOCOL-OBSERVATIONS.md)。

stdio 启动受信、版本固定的服务进程，命令不来自聊天；最小环境短期注入凭据，stdout 只放协议。远程 HTTP 使用指定认证、TLS、服务允许列表和目的地址约束。MCP 认证令牌限定目标服务 audience，平台登录令牌、模型令牌和 MCP 令牌不能互相透传；不把有 MCP 认证等同业务操作获批。

2026-07-28 的 roots 已弃用，旧版本 roots 也只是范围提示，不是 ACL。平台用受控参数、资源服务和 OS/网络边界落实访问；不把“配置了 roots”称为文件隔离。服务器发起的 sampling / elicitation 等能力默认关闭，确需启用时分别经过用户交互、成本和外发策略，不能借工具调用绕过模型预算。

## 工具调用链

1. 工具以 `connectionId/toolName/schemaHash` 唯一定位，避免同名工具冲突。发现信息只用于候选，不直接执行。
2. 工具描述、返回资源链接及提示文本均为不可信数据；服务端可信注册策略决定读/写/外发风险，不能只信 readOnlyHint。
3. 验证参数 schema、固定系统环境、数据集/路径/时间/行数允许范围及当前授权。任意 URL、自由 SQL、shell 和文件路径须专门受控，不能只做 JSON 类型检查。
4. 对需要确认的动作生成 operationHash、参数摘要和到期时间，分配有权的审批人；发送前核查计划、schema、授权与资源前置条件。
5. 工具调用使用独立 invocationId / commandKey，预占共享调用预算，资源身份与授权范围一并传给网关。总控和直连都只能经相同受控资源边界。
6. 响应限制字节/条数、内容类型与输出 schema；标注截断、执行时点和来源。资源链接须再次授权和安全导入，不自动抓取任意地址。
7. 保存工具调用事实、批准引用、参数摘要、输出哈希、用量与外部结果状态；文本回复不是工具已经执行的证明。

## 超时、重试和撤权

read timeout、连接断开、服务进程退出不能证明动作未执行。只有可信、限定的纯读取且网关明确其幂等和无副作用时才允许有界重试；其余结果未知进入核查，不用新调用 ID 重做。同键重发是否可用由工具实际支持及验证证据决定，MCP 本身不提供全业务 exactly-once。

取消是停止请求，效果以网关/工具回执为准。撤权立即阻止新调用和新下载，取消在途动作后仍核查残留查询/子进程；无法确认时保留未知事实和预算挂账。连接停用不释放现有 Binding 的唯一拥有权。

## 管理界面与验收

管理 API 草案：`POST /admin/mcp-connections` 保存受控服务与认证引用；`POST /admin/mcp-connections/{id}/discovery` 生成带版本和预算的发现任务；`POST /admin/mcp-tools/{id}/review` 固定 schemaHash、风险策略及环境范围；`POST /tool-invocations` 由执行适配器提交 operationHash、参数、批准引用、幂等键和资源身份引用。调用网关不信任模型自报权限或伪造批准；`GET /tool-invocations/{id}` 只读核查原调用，不发起重试。schema 或策略漂移返回重新审核错误，超时返回结果未知及原 invocationRef。

接入页分别显示模型访问、ACP 执行和 MCP 工具三个区域。MCP 可选择合成故障：能力未知、schema 漂移、越界参数、认证过期、调用超时；预检只输出设计上的阻断项，不发网络请求，不把红绿标记当真实工具验收。

真实验收需覆盖最小认证、令牌 audience、工具名冲突、变更清单审核、schema/风险策略、资源链接再授权、注入返回、未申请权限的写请求、响应超限、预算共享、取消及未知结果恢复。本轮均为设计要求，真实工具状态保持未验收。

整体走查补充：工具观察或 schema 修订变化通过依赖通知使待执行计划失效，原 Binding 不改写。诊断页面的预检与配置发布不同；原型用明确的“模拟变更”动作演示失效传播，不因查看诊断就偷偷修改真实配置。执行已发出且结果未知时仍按原 invocation 核查，不因计划失效创建替代调用。
