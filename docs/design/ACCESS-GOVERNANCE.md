# 接入与治理：从登记到本次执行

初始设计；所有界面与发现数据为离线合成示例。真实认证、模型发现、MCP schema、隔离、持久化和计量均未实现。本页取代把协议说明卡片作为日常接入页面的布局，原诊断演练折叠保留。

## 入口与职责

| 入口 | 管理对象 | 管理员日常操作 | 不在该页处理 |
| --- | --- | --- | --- |
| Agent 与模型接入 | Agent 连接、连接发现及模型预设 | 新增连接、配置认证与运行档案、发现模型、选择并发布预设、停用 | 业务数据库地址、环境授权和成员额度 |

“模型与执行连接”不再与接入页并列占据两个菜单。模型预设是 Agent 接入页的下一步，保留 `#admin-models` 深链接。资源目录独立保留代码、MCP 与 Skill；系统设置内完成环境绑定，权限页维护全局默认和角色上限。仍使用原有 22 个路由，菜单数量不代表新增交付范围。

## 一次完整配置示例

1. **准备运行配置**：登记只读执行节点、受控身份、允许的工作区和网络；初始原型已有合成默认项，可直接选择。
2. **添加 Agent 连接**：例如“排查 Agent B”，选择受控 ACP 直连，选择受信启动模板和运行配置。总控路线填写其受控 HTTPS 接入地址及外部 Agent 引用，实际内部调度仍由总控拥有。
3. **认证与发现**：执行器自行管理登录时，平台显示待认证、认证责任人和过期状态；明确支持宿主注入时使用凭据引用。实际连接成功后发现可用模型和能力，真实验证后才允许生产准入。原型按钮明确叫“模拟发现”，只载入固定样例。
4. **发布模型预设**：选“排查 Agent B → 其发现的模型”，设用户显示名并发布。原型不能把任意模型名称输入框当发现清单；同一实际模型的多个别名共享额度键。
5. **登记 MCP**：资源目录配置受控地址或启动模板、凭据引用、工具清单；发现后核准工具和参数范围，再发布。原型对填写的合成工具清单作显式确认，未运行真实发现。更换端点、认证、传输、工具或风险声明后要求重新确认。
6. **绑定业务环境**：系统设置 → 订单系统 → 测试环境，勾选可用 Agent / 模型组合、指定其中一个默认值、关联代码项目及版本、MCP、Skill、检查流程与上下文策略。
7. **授权成员**：授予环境、模型及流程权限，选择执行方式，默认继承全局模型额度，仅为例外成员设置覆盖。应用前看有效权限；配置好资源不等于所有成员都可用。
8. **发起问题并核对记录**：用户选择系统环境、提问；平台生成本轮准备快照并按策略确认或审批。管理员在任务 / 用户记录中核对实际采用配置及缺失证据。

依赖图：运行配置 → Agent 连接 → 模型预设；代码 / MCP / Skill 目录 → 环境资源绑定；环境同时选择模型预设和上下文策略；成员权限及流程需要与这些绑定取交集。

## Agent 接入与模型管理

列表首先显示名称、状态、已关联模型数与“配置”。详细表单只在选择后展开；新增默认停用。连接保存稳定 ID、Agent ID、接入方式、地址或受信模板、负责人、认证方式、运行档案引用及修订。模型预设保存连接、Agent、规范化模型 ID、显示名称和修订，不能只保存一个自由文本名称。

正式状态为草稿 → 待认证 / 待发现 → 已发现待验证 → 可准入；异常为认证过期、观察过期、不支持、停用。连接通不等于模型能用，更不等于工具权限已生效。实际发现结果需有观察时间、适配器版本、能力证据与有效期。环境启用前验证所需输入格式、MCP 注入、权限桥、实际模型回显、文件交付与预算门禁；不支持时明确阻断对应流程。

原型使用两个独立标志：`observation=synthetic` 仅说明合成发现操作已完成，`realAdmission=unknown` 始终不变。变更连接地址、Agent、认证、运行档案或 MCP 支持后，发现指纹失效，需重新模拟发现才能启用配置。生产系统使用规范化配置哈希及真实观察签名，不采用原型字符串指纹作为安全证明。

查看和操作要分别鉴权。配置管理员可编辑发现，权限管理员可授予已准入的模型；两者都不能因此读取用户正文。发现任务使用单独用途和预算，不传业务材料，认证失败不给任意外链。秘密写入走专门接口，普通表单仅取引用和状态。停用阻断新调用并安排已有拥有者核查；保存和“发现”都不能自动重启在途执行。

## 运行配置与业务环境的区别

运行配置回答“Agent 在哪里、以谁的身份、能做什么”；业务环境回答“本次检查哪个系统的数据和版本”。一个运行配置可被多条 Agent 连接引用，但每次运行的身份租约、代码快照、工作区与临时文件隔离。测试环境和生产环境不得因共用节点而共用数据权限。

列表显示被多少条连接引用，编辑前可见影响。字段是节点引用、服务身份、登记工作区、只读策略、终端限制、网络策略；地址和身份从受控注册表选择，正式服务不得接收随意 shell。初始范围只准许只读及受限网络，其他值能在原型里演示拒绝，不能发布为可用。停用被启用连接引用的运行档案前须调整依赖，紧急阻断可先停用连接。

真实配置还需资源配额、超时、输出限制、制品摘要、隔离证据和清理期限；这些属于技术详情。操作系统限制、资源网关和执行身份共同落实策略。worktree、路径前缀和模型提示词都不是隔离证明。原型只关联引用，未创建工作区或启动进程。

## MCP 与环境绑定

MCP 不全局永久绑定某个模型。目录注册一份服务，环境选择允许的连接，流程选择具体工具，用户授权进一步收窄。准备阶段得到 `(connectionId, toolName, schemaHash, parameterPolicy, executionIdentity)`；本轮 Agent 只获得这些受控入口。不同环境可以复用服务定义，但必须使用隔离的资源身份与参数范围，不能复用无限制令牌。

真实发现后工具新增、schema 变化和认证目的地变化均进入重新审核。MCP 的只读声明不能当实际权限证明。原型记录合成确认指纹；未确认的启用项阻止发布，仅引用该工具 / schema 的待确认计划因相关语义变化失效。真实 schema 与能力保持未知。关闭服务的设计应支持紧急撤权并保留依赖记录；原型目前采用先调整引用再停用的发布校验，不冒充实时吊销服务。

## 上下文策略与记忆条目

上下文策略与环境绑定，包含输入预算、输出预留、历史消息上限和长期记忆方式，支持新增、草稿、发布及停用。实际可用输入必须取策略与该 Agent / 模型已验证窗口的交集；预算未知时不能发送无限输入。原型只固定策略快照，没有实现 tokenizer 或真实摘要压缩。

材料顺序是可信平台规则、已授权的系统 / 项目 / 环境背景、当前问题、必要证据、来源可追溯的历史摘要，最后是符合策略的已审核记忆。字段白名单、来源授权、脱敏及注入防护在组装前完成。超限保留必需条件，裁剪非必要材料并显示来源被截断；不能裁掉结构化权限约束。

记忆列表独立显示状态、环境和来源可访问性。打开详情查看来源结果修订、作者、适用范围及内容，再审核 / 启用。发布记忆策略不自动批准候选；审核条目也不自动打开所有环境的记忆。个人记忆须匹配提交人，同环境记忆仍需原来源 ACL；原型只有一条合成来源、固定所有者及环境，不代表真实检索或租户隔离。

来源撤权立即停止后续引用，相关旧结果隐藏或标注来源失效；删除先进入待回执，等待正文、索引、摘要及外部副本处理。真实实现需批次、失败重试和责任人；不能把一次页面点击称为全部副本已删除。原型保留候选、审核、启用、撤销、待删除等模拟状态。

## 用户权限与记录排查

成员页保留列表 → 设置抽屉 → 确认保存。抽屉展示草稿有效环境和 Agent / 模型交集，以及执行方式和额度继承来源；后台权限不由普通成员的模型权限推导。自提权、越权环境、缺少理由、过期修订阻止保存。暂停阻断新操作，不自动宣称已取消外部工作；恢复不复活旧批准。

记录页先按审阅角色和范围过滤元数据，再显示本轮执行配置摘要：固定连接 / Agent、请求模型与实际模型、运行配置、上下文策略、MCP 工具及额度来源。历史样例缺少快照就显示“未记录”，不拿当前配置补写。完整上下文正文、代码和附件不应默认出现在元数据里，原型摘要只含配置引用；深层合成诊断不是生产授权方案。

正文必须用途理由及短期租约，切换身份、关闭审阅、超时和撤权后隐藏；附件及产物下载另行授权。排查顺序为配置准入 → 认证与实际能力 → 用户范围 → 额度 / 审批 → 原执行事实 → 产物状态。结果未知交由执行管理员查原拥有者，不显示“换个 Agent 重跑”的快捷按钮。用户验收结果始终由用户或获准负责人独立确认。

## 发布与执行衔接

配置按对象保存草稿；默认只发布当前对象，关联修改可由管理员勾选组成显式变更集。候选配置 = 已发布状态 + 所选对象；先检查依赖及每个对象 expectedRevision，再原子发布这一变更集、审计与 outbox。未选草稿不参与校验、不被发布、不被放弃。取消保留草稿，放弃默认仅作用于当前对象。观察任务、认证状态和发布不是同一事务，原型内存状态不证明服务端 CAS。

执行准备固定环境允许的模型、连接与运行档案修订、上下文策略、资源绑定、用户授权及额度策略。只有本计划实际依赖的语义配置变化才使待确认计划失效；无关系统或纯展示名称变化不影响；在途绑定不迁移，当前停用 / 撤权优先于旧快照。后台内部 Agent 分工与重试仍归原执行后端。前台“没有可用模型”应给出原因，默认项停用后不得静默切换其他 Agent。

离线交付只验证管理路径、引用关系、草稿生效、拒绝和快照保留。后续真实验收仍须包括两种后端共同契约、认证失效、发现漂移、环境切换资源隔离、权限桥、内外层预算、正文和附件 ACL、断线核查及不重复执行。

接入方式或 Agent 身份发生变更后，旧模型预设的连接 / Agent 标识必须重新对齐；不允许新 Agent 沿用旧 Agent 的额度键。原型在配置发布和计划准备两处拒绝身份不一致；正式服务优先采用新连接身份及独立修订，原 Binding 保留旧身份事实。

首次开通演练也沿用上述依赖顺序：运行配置 → Agent 与模型 → 资源目录 → 系统与环境 → 检查流程 → 权限。环境不再作为独立菜单入口；模型由 Agent 接入页进入，避免首次使用时走到旧的分散入口。该入口检查不表示已完成真实部署或空库初始化。
