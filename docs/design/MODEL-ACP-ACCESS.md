# 模型与 ACP 接入设计

初始设计评审稿；不启动 Agent、不安装 SDK、不调用模型。公开协议核查见[协议观察](PROTOCOL-OBSERVATIONS.md)。

## 四个不同的配置对象

| 对象 | 关键字段 | 责任 |
| --- | --- | --- |
| ModelAccessProfile | ID、供应商/兼容类型、endpointRef、authMethod、secretRef、数据区域、凭据责任人、允许用途、状态 | 模型访问账号与数据出口；不直接等于执行后端 |
| AgentConnection | ID、总控 / ACP、适配器修订、受信制品摘要、启动模板、宿主池、身份引用、支持协议、观察记录 | 一条受控执行接入 |
| ModelObservation | connection/Agent 版本、实际模型 ID、能力、来源、observedAt、validUntil、配置摘要、验证证据 | 区分广告能力、发现能力与已验证能力 |
| ModelPreset | 用户显示名称、连接与 Agent、实际模型引用、模型访问档案引用（若宿主支持）、参数白名单、资源策略和回退规则 | 用户选择的受限业务预设 |

总控路线的模型账号可能由总控管理；ACP Agent 也可能自行登录和管理模型。此时平台只保存外部账号状态与责任引用，不把平台密钥注入不支持该方式的 Agent。只有明确支持平台管理凭据的受控宿主才由秘密管理器按需短期注入。纯模型 HTTP API 不是 ACP；未来若要由平台自行驱动工具循环，必须另评审最小执行宿主，不能偷变成第三套未治理的执行引擎。

API Key、OAuth、外部登录是三种不同认证方式。管理端显示掩码状态、过期时间和责任人，不返回秘密。OAuth 回调绑定 state、PKCE、租户及连接；使用最小 scope，换新原子替换引用、吊销旧凭据。401 使连接进入 needs_auth，当前运行暂停或核查；不弹出任意外部登录 URL 或自动换账号。

endpointRef 指向管理员维护的允许列表，不接受用户聊天指定 URL；校验 TLS、DNS 及网络出口，避免任意代理、内网探测和凭据跨域发送。供应商数据保留、训练使用、地域、超时、流式与费用精度属于接入档案；未知即阻断敏感数据外发。

## 准入状态与模型能力

接入档案状态：draft → awaiting_discovery → observed → verification_required → eligible；认证过期进入 needs_auth，版本/能力过期进入 stale，撤销进入 disabled。观察成功不直接 eligible，必须同时通过适配器、资源隔离、审批桥接及能力匹配检查。原型所有真实接入保持 unknown / verification_required。

模型列表优先取执行器实际暴露并已确认的可选项；某 Agent 无列表能力时不得虚构列表。允许保存“请求模型”的待确认预设，但启动须取得实际采用模型的回显或明确标为不可验证并禁止要求确定模型的流程。模型 alias 漂移时刷新观察并固定当前采用 ID；不把模型名称相同当能力相同。

能力至少含文本/图片/文件输入、上下文窗口及计量依据、工具调用、结构化输出、session 恢复、原生权限、文件导入、事件持续性、硬调用限制。每项分别记录 advertised / adapter_supported / verified / unknown / unsupported。图片支持不意味着支持任意 PDF；文件 URI 支持不意味着可读取平台对象存储。上下文窗口未知时不能通过不受限拼接规避限制。

预设参数只允许能力支持的集合；温度、最大输出、推理强度等不通用字段不可盲目透传。按运行冻结预设修订、访问档案修订、连接修订、Agent 摘要与观察哈希；运行后收到不同实际模型要标记偏差并限制结论，不静默改历史。

## ACP Host 生命周期

1. 从受信注册表解析带版本/制品摘要的 Agent 启动模板。命令和参数由宿主配置，不接受用户自由 shell 字符串；秘密只通过隔离注入，不写日志或命令行。
2. 创建受限执行环境，固定 cwd、最小 env、只读代码挂载、短期资源身份及网络允许列表。stdio 为本地受控子进程优先；远程传输仅在双方确有能力、可认证并已验证时启用。
3. `initialize` 协商支持版本与双方能力；收到未知版本拒绝准入。按所选版本处理认证，发现 Agent/模型选项及支持的输入形式。
4. 新执行单元用 `session/new`，按允许能力传 `cwd` 与受控 MCP 配置。一个 Binding 映射一个被委派拥有者；外部 session 引用保存在适配器账本中。
5. 仅在协商能力允许且原拥有者可核查时恢复会话。`session/load` 等能力不是任意后端透明迁移；缺失或过期则转安全交接，不自动重放旧问题。
6. `session/prompt` 与 `session/update` 映射为 Provider 事件。原生工具请求进入策略判定和审批桥；通知去重、分片有界、stdout 只放协议，stderr 脱敏并限长。
7. `session/cancel` 通知与停止确认分开；进程退出后核查工具/子进程及副作用。租约过期只阻止新分派，不能当作原进程已死的证明。

协议会演进，ACP v1 与 v2 不能混用同一未标版本的处理分支；本轮以已核查的 v1 能力合同为基线，v2 仍按 Draft 单独评审。协商版本、schema 摘要和适配器支持范围进入连接档案，禁止因 SDK 升级自动改生产协议。

## 权限、文件、终端与 MCP

ACP 的能力声明仅决定哪些调用可协商，不构成 OS 限制。默认仅提供受限 read_text_file，不声明写文件和任意 terminal。Agent 若能绕过 Client 直接访问主机文件或网络，必须由运行隔离限制；无法限制则不准入该环境。

所有读取都映射到受控资源引用与固定代码快照，校验规范化绝对路径、真实路径、链接/挂载边界和当前 ACL。拒绝 .git 凭据、环境文件和未授权目录，返回结构化拒绝，不回传宿主绝对私有路径。需要 shell 的分析工具以专门只读工具暴露，不能因为命令名称是 grep 就允许任意 shell。

原生 `session/request_permission` 是 Agent 可选行为，平台不能依赖 Agent 总会请求。资源服务独立强制计划、参数、期限与幂等。原生选项只取 allow_once / reject_once；缺少完整桥接、请求失效或响应未知遵循[审批恢复](APPROVAL-RECOVERY.md)，不将“允许一直执行”解释为业务授权。

ACP 转入的 MCP 清单仅含经过网关治理的服务，工具和身份不得因 Agent 自带配置而扩权。Agent 的自带记忆、项目指令、插件、MCP、终端及网络功能必须清点并关闭或纳入治理；无法观察/控制时标为不适用，不能仅以提示词禁用。

## 失败与验收

管理 API 草案：`POST /admin/model-access-profiles` 保存端点/秘密引用与数据出口策略；`POST /admin/agent-connections/{id}/discovery` 创建有预算、无业务材料的发现任务；`GET /admin/discoveries/{id}` 返回认证、版本、能力与来源证据；`POST /admin/model-presets/{id}/admission` 对固定依赖修订检查准入；`POST /admin/connections/{id}/disable` 阻止新执行并安排原拥有者核查。均需配置权限、稳定命令键、expectedRevision 与审计，发现任务受调用预算约束。发现不自动发布预设，禁用不声称在途已停止。真实凭据只能经独立秘密管理接口写入，不由通用配置 API 返回。

| 故障 | 前台与后台行为 |
| --- | --- |
| 模型未知 / 能力过期 | 用户看到当前选项不可用；后台列具体缺失与责任人，不偷偷降级 |
| 登录过期 / 配额不足 | 当前执行保存引用，管理端显示恢复认证 / 额度原因；不自动改账号 |
| Agent 初始化崩溃 | 明确未提交才可修配置后新节点；提交未知先核查 |
| 输入过大 / 图像不支持 | 保留材料，提议用户选择可支持方式；不声称已分析附件 |
| 回复中断 / 进程失联 | 展示核查中，保留既有证据与预算挂账；不换后端重做 |
| MCP 或审批能力不足 | 具体操作阻断，交付可定位接管信息 |

未来适配器共同测试必须包含：总控关闭时直连基础链路；模型实际采用回显；认证轮换与失效；Agent 不请求权限但资源服务仍拒绝；会话恢复与撤权；超大输出和子进程清理；不同协议版本兼容。当前只交付设计与离线预检演示，没有真实调用。

## 整体走查的绑定规则

用户模型偏好变化不是原 Binding 的迁移。只允许在执行空闲且旧执行安全关闭后改变后续偏好，同时使待确认计划失效；新计划记录实际引用的冻结配置和当前准入修订。请求模型与实际模型观察分开，后者未知不能据此通过真实能力门槛。当前原型采用[衔接合同](END-TO-END-WALKTHROUGH.md)的共同记录核对这些字段，所有真实调用仍为 not_run。
