# 日常管理页面 UI 设计

初始设计。依据用户反馈：审批管理应当先看到列表，日常管理不需要展示复杂技术面板。仍仅提供离线设计与原型。

## 页面结构

日常入口采用“列表 → 详情抽屉 → 必要时确认”。首次进入不自动打开某条详情；不把列表和完整诊断同时铺在页面。详细接入配置仍位于对应设置页。

| 页面 | 列表首屏 | 点开之后 | 次要信息 |
| --- | --- | --- | --- |
| 审批管理 | 待审批 / 已处理 / 全部；关键词、环境筛选；检查事项、申请人、环境、状态、提交时间、操作 | 本次检查范围、申请信息、审批意见；底部固定批准 / 拒绝 | 固定计划修订、执行拥有者、资源引用和审计折叠展示 |
| 执行管理 | 用户请求、申请人、环境、状态、时间；常用状态切换 | 处理进度、当前结果、停止入口、同一用户记录入口 | NodeRun / Binding、配置快照、技术事件按需展开 |
| 用户与权限 | 成员、角色、可用环境、执行方式、账号状态 | 单个成员的执行方式、角色、环境、Agent / 模型额度与变更理由；保存或暂停 / 恢复 | 授权修订与生效规则折叠展示 |
| 用户记录 | 获准范围的问题、提交人、环境与状态 | 基础信息和有用途授权的对话内容 | 后台处理时间线和配置 / 上下文引用折叠展示 |

不添加无实际操作价值的统计大屏、批量批准或任意重跑。通用搜索支持按钮或 Enter 应用，自动去除首尾空格；可重置关键词 / 环境 / 状态，筛选切换回到第一页；列表支持分页，返回后保留关键词、环境、状态。状态始终同时使用文字，不能只靠颜色辨认。

## 审批列表和详情

每一行代表一份具体审批计划，以记录 ID + contextRef 区分同一问题的多次申请。历史行保存它自己的输入修订、有效期、决策与准备快照，不用当前新计划覆盖历史。自动授权决定单独显示“自动授权”，不能伪成人工批准；每条自动执行也保留自己的准备快照，历史条件不跟随后续输入变化。

待审批页只列当前等待责任人的计划；已处理页包含批准、拒绝、过期或失效，以及自动授权审计。单条列表动作先进入详情，不在未审阅范围与参数时直接批准。批准只决定这一份固定计划，不等于执行完成或用户确认解决。

详情主体先给固定计划中的用户问题、本轮补充、只读范围与环境，再提供技术引用。审批意见在决定后进入该计划的历史，不依赖暂存输入框恢复。正式服务应返回经审批用途授权的固定操作摘要和参数，不要求审批人从聊天全文或 Agent 自述推断范围；显示摘要与 operationHash 必须对应同一不可变计划。当前原型为合成只读示例，不能充当真实操作摘要或权限验收。

审批意见在同页关闭 / 重开详情时保留；拒绝必须至少 5 字。确认窗口绑定 contextRef 和目标，提交前再次检查审批资格、计划修订与有效期。已处理 / 已失效行没有再次批准入口。服务端冲突、撤权、失效或执行事实未知时，展示原因并要求重新审阅，不自动重提。

## 易用性与界面状态

- 宽屏使用完整表格；窄屏每行转为紧凑记录布局，保留事项、申请人、环境、状态、时间与操作。抽屉窄屏占满宽度，内容独立滚动，底部操作始终可见。
- 打开详情后焦点进入关闭按钮；Tab 留在抽屉；Escape 或关闭按钮返回触发入口。确认窗口取消只关闭确认窗口，回到抽屉原动作；关闭详情不作审批决定。
- 无匹配记录时显示“清除筛选”；没有本次提交时引导提交问题或查看示例；无权限时显示角色 / 范围提示，不把无权限与无数据混为一谈。
- 读取列表、读取正文、审批、暂停用户及停止执行分别鉴权。配置管理员不自动拥有用户记录和审批权。演示角色控件只是原型评审工具，正式产品由登录身份决定。
- 同页更新会重新核查当前可见范围；正文租约失效时隐藏内容。技术信息折叠不是权限控制，未获权的数据不能返回浏览器。

正式服务还需提供加载、网络失败、分页游标失效和操作冲突状态；失败时保留筛选和未提交意见，不显示成功。当前离线原型没有真实网络或事务，不能把本地同步读写当作上述状态已验证。

## 示例与本次提交

直接打开审批页时，以清楚标注的示例数据展示 3 条待审批、2 条历史项，便于评审页面；首个管理入口选择与该页匹配的演示角色。用户手动切换过角色后，按已选角色显示范围，不为展示示例静默提权。

已有本次提交的计划时默认显示同一会话账本；也可显式切换“仅本次提交”或“示例数据”。示例和本次提交互不混合：示例批准 / 拒绝只更新示例列表，不创建会话、执行绑定、结果或外部调用；列表和详情均说明这一边界。空的本次提交不会被示例伪装成真实待办。

## 日常操作可用性补充

- 成员支持姓名 / ID 搜索和账号状态筛选；无匹配结果可一键重置。关闭成员设置只隐藏编辑区，未保存草稿按“演示管理者 + 成员”在当前页面内存中保留，并显示未保存标记。关闭不授予权限；刷新仍清空草稿。不同身份不复用彼此的草稿。成员设置完整显示现有环境授权，区分可新增范围和已存在的其他授权，不能只显示固定三个环境。仅填写理由也是未保存草稿，可明确放弃。
- 可明确“放弃修改”，恢复已保存设置；保存仍要有理由及确认。提交成功清除对应草稿，授权修订变化后不自动复用旧草稿，服务端仍须 CAS 拒绝冲突。
- 审批、执行和记录提供明确的搜索操作；执行状态下拉与当前状态页签一致。列表关闭详情后保留筛选和输入。
- 配置长表单的应用 / 放弃栏保持可见，没有修改时禁用。一次应用覆盖全部未应用草稿，确认页列出所有变化；不是只保存当前页。校验错误列表能跳到具体配置、资源类型及字段，纠错不发布其他草稿。
- 环境可分别跳到代码项目、MCP 或 Skill 的目录页，再返回原环境；修改都留在同一配置草稿。选择开关及下拉后保留键盘焦点，避免每次更新都回到页面顶部。

[可用性走查](../reviews/USABILITY-REVIEW-20261025.md)记录本轮发现、改动和证据；[usability-checks.cjs](../prototype/tests/usability-checks.cjs)检查上述实际路径。所有模拟、截图和浏览器脚本检查均不构成用户实用性验收或真实服务证明。

系统设置的详情内列出所属环境，不单设环境主菜单；全局默认额度和成员例外放在既有权限页及成员抽屉的折叠区域，详见[配置与执行衔接](SYSTEM-CONTEXT-QUOTAS.md)。

## 接入治理的日常配置

Agent 连接、运行配置和上下文策略采用列表 → 按需展开配置 → 预览发布；高级诊断默认折叠。Agent 详情可直接创建带入本连接的模型预设，记忆列表可直接打开条目操作。用户记录新增本轮执行配置摘要；正文仍受独立用途租约约束。完整页面规则见[接入治理操作设计](ACCESS-GOVERNANCE.md)。
