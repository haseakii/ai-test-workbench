# 首次开通与完整使用试验

初始设计评审稿。目标是让一个测试团队从空部署走到第一次有依据的排查，再让管理员能找到同一条处理记录。当前可以验证页面操作和离线联动；真实部署、身份、模型及资源执行尚未实现。本页将两类证据分开，最后集中列出待用户审批的取舍。

## 首版产品的出发点

日常工作是“我有一个问题，帮我查清楚”。测试人员选择系统、环境，发问题、补材料，在需要时确认范围，最后查看依据和文件并验证。可用检查来自已发布配置和当前权限，用户无需认识 ACP、MCP、Skill、执行绑定或上下文清单。

管理员日常处理三件事：开通成员和配置环境、处理待审批申请、排查未完成的问题。默认列表给出状态和下一步；详细计划、记录和配置在选中对象后展开。首次安装引导只在未初始化时出现，完成后从设置中按需查看，不占据日常工作台。离线原型的“首次开通演练”位于管理侧栏的“设计资料”，不会强迫每次聊天重新注册。

## 首次部署与管理员引导

拟采用模块化单体加一个受控执行节点。以下是将来部署的操作契约，不是目前可运行的安装命令；仓库尚无业务服务或部署包，不能把打开 HTML 称为部署成功。

| 顺序 | 操作者与输入 | 服务需要证明的事实 | 失败时的处理 |
| --- | --- | --- | --- |
| 1. 准备部署 | 部署负责人选定内网访问地址、TLS、身份源、业务库、对象存储、秘密引用 | 应用可启动；存储可写、迁移可恢复；日志无秘密；凭据不进浏览器 | 展示具体缺项，执行分派保持关闭 |
| 2. 建立组织 | 部署负责人通过一次性、限时引导绑定企业身份 | `(issuer, subject)` 校验成功；组织和首位管理员事务创建；引导令牌仅存哈希、一次消费 | 同键查询创建结果；并发不能产生第二个首位管理员；不提供公开抢注管理员入口 |
| 3. 配置团队 | 首位管理员分配配置、权限和审批责任 | 首位管理员不自动拥有用户正文或资源执行权；新增敏感权限须独立复核 | 没有第二位复核责任人时保持受限，不用自批填补 |
| 4. 配置最小场景 | 系统、环境、一个流程、模型连接、只读 MCP、需要的 Skill / 代码项目 | 发布修订完整，审批人实际可接单，资源策略有明确执行身份 | 可保存草稿；界面说明哪个检查不可用及缺项 |
| 5. 校验执行能力 | 对选定后端、模型、隔离、工具和权限桥作获授权探测 | 观测绑定制品 / 协议 / schema / 策略修订及有效期；所需能力有证据 | 未知或过期则阻断取证，不能用“连接成功”替代准入 |
| 6. 小范围试用 | 先开通一个测试成员和一个环境 | 一条真实只读排查可交付并由用户验证，重启恢复无重复执行 | 保留失败证据和原拥有者，修复后复验 |

健康状态分开：应用存活、业务服务可用、指定环境的指定流程可执行。某个执行器不可用时，用户仍能登录、查看获权历史、提交仅收集的问题；页面明确不能取证。禁止一个全局绿色“健康”暗示全部工具、模型和环境都可用。

引导入口完成后关闭，重启不得重新开放。管理员全部离职的恢复由部署负责人按独立恢复流程完成，保留操作者与授权证据；不增加网站上的通用后门密码。备份恢复先禁分派，对账未终结 Binding 和 outbox，再恢复接收新任务，不能把旧备份任务重新执行一遍。

## 登录、注册和成员开通

建议初稿采用“企业身份登录 + 申请加入 / 管理员邀请”，暂不自建密码注册找回体系。登录证明身份，成员开通决定组织内权限；两者分开。新用户首次登录只看到工作台名称、申请用途和申请状态，不获得环境列表或用户内容。即使身份源允许全公司登录，也不默认全公司都能查询系统。

| 状态 | 谁可推进 | 操作和下一状态 | 原子约束 |
| --- | --- | --- | --- |
| 未加入 | 已验证身份本人 | 提交用途 → 待开通 | 服务端绑定身份与组织；同身份仅一条有效申请；重复键返回原申请 |
| 待开通 | 可管理该组织的权限管理员 | 选择角色、环境、执行方式、理由 → 正常 | CAS 核对申请 / 授权修订；成员、授权、审计、通知 outbox 同事务；不得越过可授予范围 |
| 待开通 | 权限管理员 / 本人 | 拒绝 / 撤回 → 已关闭 | 保存理由与决定；无授权残留；重新申请产生新申请关联旧记录 |
| 正常 | 权限管理员 | 暂停 → 已暂停 | 撤会话 / 租约、授权修订、审计与撤权通知同事务；在途执行另发停止并核查 |
| 已暂停 | 权限管理员 | 复核范围后恢复 → 正常 | 新授权修订；不恢复旧批准或重放旧任务 |

离线演练覆盖申请、待开通、授予环境、开通、按策略审批和交付；拒绝 / 撤回、邀请领取、真实登录和并发事务留待实现，不将其标成已实现。原型用固定合成身份、不收密码，不能验证身份欺骗或跨租户安全。

正式邀请绑定组织、身份源、指定身份或经验证的匹配条件、可授予范围、有效期和一次性令牌哈希。领取后仍复查邀请人当前权限、角色和环境策略。身份不匹配、撤回或过期返回可重试的新邀请路径，不泄露他人账号存在性。邮件地址只能是显示和经过验证的匹配属性，不能取代稳定身份键。

前台只填写用途和可选申请说明；不接受浏览器提交的 tenantId、subjectId、管理员角色或执行权限。列表和通知仅向有权限处理该申请的管理员展示。成员开通通知与执行审批通知各自引用对象、修订和当前状态；通知失败不回滚已经保存的决定，原事务 outbox 重试通知，不能重做开通或执行。

## 服务接口与对话衔接

| 入口草案 | 请求 / 返回 | 边界 |
| --- | --- | --- |
| GET /session | 身份、成员状态、可进入工作区；未开通时不返回环境 | 真实 SSO 回调由服务端校验 issuer、audience、nonce/state；浏览器角色选择无权限效力 |
| POST /membership-requests | 用途、幂等键 → requestId、待开通、revision | 身份与组织由已验证会话及受控工作台入口解析；不相信客户端归属 |
| GET /membership-requests/current | 本人的当前申请和决定 | 不可遍历其他申请 |
| GET /admin/membership-requests | 范围内待开通 / 已处理列表 | users.manage；列表不包含用户对话正文 |
| POST /admin/membership-requests/{id}/decision | 固定申请修订、角色、环境、执行方式、理由 → 决定回执 | 授权交集、CAS、原键查询；超时不自动换键再创建成员 |
| POST /session/logout | 退出回执 | 服务端撤销会话，前台清缓存；在途执行按独立撤权 / 停止规则处理 |

开通完成后重新获取 `/session` 与 `/workbench/options`，新建问题快照。环境列表取成员授权与已发布环境交集，流程、工具、Skill、模型继续按[配置到执行](USER-FLOW-AND-CONFIG.md)解析。没有有效环境时显示“尚未分配可用环境，请联系管理员”，不能给一个默认环境绕过开通。

每轮推进依次区分：消息已保存 → 计划已确定 → 等待批准（如需要）→ 执行拥有者已接收 → 证据与产物已导入 → 待用户验证 → 用户确认。成员开通成功、HTTP 200、模型回复完成和工具调用成功，都不能替代后续阶段事实。具体事务与执行接口沿用[服务执行](SERVICE-EXECUTION.md)、[Provider](EXECUTION-PROVIDER.md)、[审批恢复](APPROVAL-RECOVERY.md)。

## 完整场景与证据门槛

业务样例：“订单报表与明细金额不一致”。同一名测试人员、同一测试环境、同一已发布流程贯穿全程。初次实验先使用人工可复算的合成夹具；未来用真实执行服务读取该夹具，仍不得称作客户业务验收。

| 阶段 | 实际操作 | 通过需要的证据 | 当前证据级别 |
| --- | --- | --- | --- |
| 部署 | 空存储启动、一次性绑定首位管理员、重启 | 部署制品摘要、迁移 / 启动日志、二次引导拒绝、重启数据保持 | 设计；未运行 |
| 配置 | 建一个系统 / 测试环境，发布模型、只读资源和固定流程 | 发布修订；准确工具白名单；不可用依赖阻断 | 离线表单与依赖检查；真实能力未知 |
| 注册与管理 | 新成员申请、管理员仅授订单测试环境、逐次审批 | 申请 / 决定 / 授权审计同一身份；不能看到未授权环境 | 离线共同成员记录；SSO / 事务未运行 |
| 对话 | 提问并补齐时间、时区、状态、币种 | 消息保存回执、固定范围、解析过的附件、计划版本 | 脚本回复；附件只有文件名 |
| 审批 | 用户等待，负责人处理列表内具体计划 | 计划哈希 / 有效期 / 责任人；执行前复查；过期重新授权 | 离线审批；原生权限桥未运行 |
| 执行 | 一个拥有者读取夹具并确定性计算差异 | 实际模型观测、工具审计、代码 / 部署与取数时点、只读拒绝证据 | 内存模拟；actualExecution=not_run |
| 查看与验收 | 下载差异文件、核对原始行、确认本结果 | 文件哈希、来源与计算复算、用户对该结果修订的独立确认 | 合成 CSV 可下载与复算；业务证据未运行 |
| 管理排查 | 按同一用户 / 问题定位任务与审批，申请正文租约 | 跨层引用一致、最小内容权限、用途审计、过期拒绝 | 离线记录与租约检查；服务端 ACL 未运行 |

当前本地操作入口：[首次开通演练](../prototype/index.html#getting-started)。浏览器用例 `onboarding-checks.cjs` 串起成员开通、对话、负责人审批、文件交付、用户确认和管理员审阅；它不能证明部署或真实服务可行。现有记录存在时禁止演练重新初始化该用户，以免把真实日常操作设计成“重置后继续”。

补充连续配置走查：`complete-journey-checks.cjs` 在预置离线目录中新建运行配置、上下文策略、ACP Agent、模型预设、代码项目、MCP 和 Skill，绑定订单测试环境及流程，再完成成员申请、开通、对话、审批中心批准、交付、用户验证和管理员审阅。配置开始后不刷新或重置；核对同一配置修订、额度组合、计划、Binding 和结果版本。输出见[连续链路证据](../reviews/initial-design-checks/complete-journey.json)。这是新增配置贯穿页面的证据，仍不是空库部署、真实身份、Agent 运行或真实取证。

真实试验必须包含失败路径：重复点击提交与并发成员开通；登录过期和撤权；配置发布后旧计划失效；审批等待超过原生期限；start 回执丢失；断网重连和服务重启；结果文件校验失败；用户认为未解决；管理员无内容权限。每条保留预期、实际、原执行引用、日志 / 文件哈希和未通过原因。总控路径与总控关闭后的 ACP 直连分别跑同一组夹具和权限约束，不能只证明其中一条路径。

## 待统一审批的事项

| 事项 | 初稿建议 | 需要最终确定的内容 |
| --- | --- | --- |
| 首批范围 | 一个测试团队、一个系统和测试环境、只读固定检查 | 试点系统、负责人和验收人 |
| 登录开通 | 企业身份源；申请 / 邀请后开通；未开通零环境权限 | 可用身份源，是否有外部成员，本地密码是否确实需要 |
| 用户交互 | 连续对话，按需查看问题信息；管理员采用历史版列表 / 表单 | 统一确认当前交互方向，哪些字段仍可删除 |
| 执行策略 | 新成员默认本人确认或负责人审批，自动只读显式授予 | 哪些用户 / 环境允许自动检查、审批代理与超时责任人 |
| 首次技术试验 | 获批后实现最小服务，先读取合成夹具，再接授权测试资源 | 部署主机、后端与 Agent 制品、模型账户预算、资源访问范围 |
| 数据与运维 | 平台独立业务库和文件存储；记忆默认关闭 | 保留期、备份恢复目标、正文审阅责任、删除 / 保全规则 |

本页完成设计上的操作串联，不提前确认真实可行性，也不为填满清单而连接资源。用户统一审批后，再按实际获准范围开始实现和实机试验；当前持续保留未运行项。
