# 系统下的环境、执行上下文与用户额度

状态：初始设计与离线原型，未接入真实资源或用量账本。

## 系统设置中的环境

主菜单只保留「系统设置」。选择系统后，基本信息下方列出所属环境，可添加环境或进入环境配置；环境页显示所属系统与返回入口。环境列表按系统过滤，新增默认归属当前系统。旧 `#admin-environments` 链接保留为兼容详情入口，不再是独立菜单。

系统拥有业务背景、负责人和常用问题；环境拥有说明、时区、预期数据延迟、部署版本标记，以及代码项目版本、MCP、Skill、流程和策略绑定。代码项目继续由资源目录复用，保存模块职责、Git / 本地来源及路径范围。环境可绑定多个项目，同一项目可用于多个环境，但版本与资源授权分别固定。更改环境归属不会迁移既有会话；必须重新核对权限，不能靠改名或改描述把测试环境变成生产环境。

日常操作：系统设置 → 订单系统 → 测试环境 → 关联代码项目 / 工具 → 预览并应用。用户仍只选系统和环境，不需要填写后台接入参数。

## 结构化资源与背景说明共同进入执行

单纯拼接一段描述不足以确定执行范围。平台按下表生成两部分内容，使用同一准备清单与修订绑定。

| 输入 | 模型获得什么 | 执行服务必须检查什么 |
| --- | --- | --- |
| 系统说明 | 业务对象、术语、检查目标 | 系统 ID、启用状态及用户范围 |
| 项目说明 | 本流程需要的模块职责、代码组织 | 项目 ID、修订、代码快照、只读路径、执行节点或 Git 来源 |
| 环境说明 | 测试数据特点、口径、已知限制 | 环境归属、资源身份、工具参数约束、运行身份 |
| 时区、延迟、部署标记 | 标注为配置背景的解释条件 | 对照实际取数时点、部署版本；未知不能补成已确认 |
| MCP / Skill | 本流程获准的工具 schema、版本化方法 | 环境 ∩ 用户 ∩ 流程 ∩ 真实执行器能力；Skill 不授予权限 |

流程固定为：用户选择 ID → 服务端鉴权与选择已发布流程 → 解析当前有效资源 → 确认 Agent / 模型 → 组装背景与结构化清单 → 额度预占 → 审批（如需）→ 执行前复查 → 委派唯一拥有者 → 证据与结果交付。

背景只包含显式允许的说明字段，带来源 ID、修订、摘要和 `configured_background` 标签；它不是高优先级指令，也不是观测证据。不得把完整配置对象、Token、凭据引用、连接串或不相关环境塞进提示词。代码正文和附件须另行授权、读取、脱敏及预算裁剪；不能为了缩短提示词丢掉结构化约束。描述中出现“忽略审批”等文字不能改变策略。

多项目只加入本节点需要且已授权的项目；原型按流程的读代码声明选取环境关联项目，正式服务应保存显式项目选择及理由。项目或环境缺失、停用、归属冲突时拒绝准备；说明可空，必要业务条件缺失时追问。描述与真实证据冲突时保留两者来源，要求核实或限制结论。

准备清单固定系统 / 环境 / 项目修订、资源快照、上下文摘要和额度策略。待批准期间任何相关变更使旧计划失效；审批后再次核对。正在执行的 Binding 保留原快照，当前撤权或额度下调在下一次调用前阻断，不能换后端重放。管理员通过任务记录查看本轮用了哪些背景、资源和额度策略，不使用当前配置伪装历史执行事实。

## 用户按 Agent 和模型分配额度

默认配置入口在「权限配置 → 全局默认额度」；例外入口在「用户与权限 → 成员设置 → Agent / 模型额度」。每个组合显示继承来源，支持单独设置或恢复继承。不新增主菜单，不让用户逐条填写相同数值。

额度键为 `(tenantId, subjectId, connectionId, agentId, canonicalModelId)`。用户名称、Agent 显示名和模型别名都不是计量键；两个预设映射同一真实组合共享账本。原型使用稳定的 demo 标识，实际模型确认仍未知。模型未知或运行时换模型时不得借用其他模型余量；重新核对并预占目标组合，无法确认则阻断。后端重试、内部子调用、自动标题与其他模型辅助调用也归到实际调用组合，另标用途，不因入口不同逃逸计量。

初始配置采用完整策略继承：没有用户例外即继承全局默认；有例外则整行覆盖，删除例外恢复继承。角色权限、平台 / 环境硬上限仍取更严值。新用户及新增组合自动继承；停用模型不会删除用量或例外。配置额度不会授予模型使用权。

| 字段 | 含义 |
| --- | --- |
| 每日平台请求轮次 | 平台接纳的模型用途请求轮次，理解与取证均计入；不是执行器内部模型调用数 |
| 每日调用次数 | 仅在后端可靠上报时统计真实模型调用；只有可验证调用前拦截时才能强制限制 |
| 每日 Token 目标 | 有可靠回执才统计规范化用量；默认是预算目标而非硬门禁。硬限额流程必须有验证过的强制能力；缺失不记零 |
| 单轮内部调用目标 | 有内部调用拦截能力时才是硬上限；与角色目标取更严值，不支持时明确标为仅统计 / 未上报 |
| 并发执行上限 | 用户 / Agent / 模型组合的活跃执行数；角色级用户总并发另外限制 |

示例默认：每日 100 个平台请求轮次、并发 1；模型统计目标为每日 100 次、100000 Token、单轮 10 次。默认允许平台约束＋已知用量统计，内部硬限额要求可显式开启。未上报 / 可统计 / 可强制三种能力分别显示；合成能力不是实机证据。均可修改，整数 0 明确禁止新调用，空值不是无限额度。每日时区采用组织配置，初始原型为 Asia/Shanghai；服务端计算周期边界，跨日保留旧周期账本与未结算预占，不重置在途调用。例外允许提高默认值，但不能越过管理员可授予范围和更高层硬上限，禁止用户自行提额。

## 预占、等待与结算

接纳事务同时创建不可重复的预占和执行 Outbox；键包含用户组合、周期、操作 ID 与实际调用 ID。审核期间可持有短期预占；过期释放必须有“尚未发起调用”的确定事实，批准后重新取得预占并复查。单次调用额度与 Token 上界在受控网关 / 宿主原子取得，实际回执按稳定调用 ID 幂等结算，重放回执不重复收费，真实重试调用独立计量。

费用、Token、调用次数和并发分别记账。费用可以延迟结算；估算与真实值分列。未知用量保持未结算，保留预占；只有能证明仍在已授权上界内时才继续，否则暂停新调用并核查。拒绝、取消和断线不自动表示未消耗，不重复释放。默认或例外变更不清空当期消耗；降低至已用量以下时剩余额度为零；在途操作先核查，未来调用按最新策略决定。

若总控 / ACP Agent 无法提供实际模型、子调用用量或可强制的调用前拦截，不宣称实现硬额度。可将能力标为不支持并拒绝需要硬限制的执行，或由责任人明确采用受限且可计量的路径；不得静默切换后端。首次正式实现需验证双重预占、并发竞争、重复回执、跨日、审批过期、未知结算和内部重试。

## 能力分级与跨连接总账（本轮收敛）

平台自控层包括请求轮次、排队与已分派并发、附件大小和工具网关行数；执行器回执层包括真实模型、Token、费用及内部调用数；强制层还要求覆盖所有内部调用的调用前拦截、可计算的预占上界和取消 / 结算证据。超时只停止后续分派或请求取消，不保证外部费用立即停止。

ACP 一次 `session/prompt` 可含多次模型交互，`usage_update` 可选；`used/size` 为上下文占用与容量，不是累计消费。依据：[ACP v1 Prompt Turn](https://agentclientprotocol.com/protocol/v1/prompt-turn)。因此仅有 ACP 连接或一个可选的用量事件不构成硬额度能力。

按执行器展示“未上报 / 可统计 / 可强制”，记录观察时间、制品和证据。要求硬限额的流程对 unknown / unsupported 拒绝；非硬限额流程可以明确采用平台限流＋已知用量统计，并显示未知消耗。用量读取、取消和核查不因额度耗尽而被禁止。

用户跨连接总账键 `(tenantId,subjectId,period)` 与模型分项键分别维护，调度时在同一事务取得总账和分项预占。两个 Agent 连接不得各自独享一份用户总额；未知消耗保留为未结算，不重复预占、不记零。总控根任务汇总与子任务明细只能选一个计费来源，按 Provider 调用 ID 去重。当前原型只展示键、能力和准入分支，尚无真实余额、数据库事务或费用硬控制。

开发规划补充：总账上限是独立的用户级平台策略，不等于各模型额度相加，也不由全局模型默认值自动乘以模型数量。建议沿用权限配置的高级区域设置用户总轮次 / 总并发默认上限，成员例外只能在可授予范围内提高；模型例外不自动提高总上限。首批建议总轮次 100/日、总并发 1，均为待评审初值。原型尚未实现该总账编辑与余额服务，未来有效额度预览需明确显示总账和分项哪个限制生效。完整事务及跨日规则见[数据与事务](../development/DATA-AND-TRANSACTIONS.md)。
