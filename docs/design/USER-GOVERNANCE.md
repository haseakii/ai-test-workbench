# 用户、权限与管理记录审阅

初始设计评审稿。管理后台需要支持用户管理和排查记录查阅，同时明确“能管理配置”和“能看用户内容”是两项独立权限。

## 身份与可管理范围

正式身份由受控 IdP / SSO 提供稳定 subjectId、租户和成员关系；会话 Cookie 安全属性、会话过期、登出与撤销由平台处理。原型的角色切换仅用于合成预览，不构成登录实现。

授权是角色与对象范围的交集：tenant、系统、环境、资源、用途、期限、所有者/协作者。角色只能赋予管理者自身可授予的权限集合；禁止通过编辑角色间接自我提权、给自身增加内容读取或审批权。直接授予和角色成员变更同样检查 grantableScope。敏感 / 生产角色变更采用独立复核，不由原操作人自批。内部测试初始化可由部署负责人显式授予同一负责人配置与有限只读审批职责；这不是普通成员自提权，也不自动授予所有正文。

| 管理角色 | 允许 | 不能由此推导 |
| --- | --- | --- |
| 配置管理员 | 发布获管系统、环境、接入与模型策略 | 用户正文、附件或所有审批权 |
| 权限管理员 | 查看成员，暂停成员，授予其可管理范围内角色/环境 | 自我提权、全租户内容读取 |
| 支持审阅员 | 获准范围的记录元数据、按理由临时正文租约 | 任意下载、修改用户消息、替用户确认解决 |
| 审批责任人 | 指派给自己的固定操作审批 | 更改计划、代行资源身份或验收结果 |
| 审计读者 | 已脱敏的变更/读取事实 | 原始客户材料和秘密 |

用户列表显示 subjectId、名称、成员状态、角色、范围、授权修订与最近使用时间；不显示密码、令牌或不必要个人信息。查询按管理范围过滤，分页与导出分别授权。新增用户通过已选定的成熟身份服务邀请或同步，不能用任意自填用户 ID 绑定已有用户。

## 用户权限变更

草稿展示角色、系统环境、到期时间、理由和基础授权修订；预览有效交集后提交。服务端校验 grantableScope、禁止自我提权、审批责任和 CAS，在一笔事务内写 grants、authorizationRevision、审计与撤权通知。冲突返回 409，保留草稿并请求重审。

暂停用户：立即吊销平台会话与内容租约、拒绝新命令、失效缓存；向所有在途执行发撤权/取消并核查，不显示“暂停用户即所有外部动作已停止”。恢复用户不自动恢复旧批准、不重发旧任务，仍须新授权或检查点恢复。删除或离职保留必要审计引用，清理个人资料与材料遵循保留/保全政策。

审批人与提交人可重合仅在实际策略允许时成立；不因“用户点击允许”默认具备批准权。权限撤销使待审批/已批准但未执行动作失效，具体恢复遵循原生请求与业务审批两层合同。

## 记录列表和内容审阅

管理记录页可按用户、系统环境、时段、问题状态、运行状态及 correlationId 过滤。默认只给脱敏标题、所属用户、固定范围、待验证/失败/核查状态、用量等级及最后活动时间；列表行数和搜索摘要也经过授权。没有正文权限时不返回正文再在前端隐藏。

打开一条记录先显示元数据、执行引用、时间线、未知项和证据状态。正文、附件、事件详情、产物与接管包分别检查 ACL；“可以看会话”不意味着可以下载附件。禁止把隐藏思维链当排查记录，保留用户可见消息、工具/审批事实与可审计摘要即可。

内容审阅采用显式用途租约：记录工单/理由、目标会话、允许字段、有效期、审阅身份和授权修订。建议有效期 5 分钟，具体待责任人确认；过期/撤权立即拒绝继续读取和缓存回放。租约创建与每次读取均审计，审计写入失败则拒绝敏感读取。日常支持只读；不能改消息、重执行任务或代用户验收。

特殊紧急访问需独立审批与受限时长，原型不提供万能“超级管理员”。支持人员和用户原则上可查看与自身有关的访问事实，通知策略待产品评审，但系统必须保留可追责记录。

## 管理记录与执行事实关联

记录详情串起消息、输入采用、NodeRun / Binding、总控 task 或 ACP session、计划审批、工具调用、上下文清单、代码/数据来源、模型实际选用、产物导入、费用和用户验证。Provider 内部细节只显示经授权且已返回的事实，unknown 保持未知。费用显示 actual / estimated / unreported，不用空值变成 0。

事件时间线可重放浏览但不触发执行；“继续处理”是需要用户/责任人授权的新命令，不能作为后台审阅的隐式动作。结果未知时管理员也只能核查原拥有者、发停止或移交责任，不能直接换执行器重做。

## 原型与未来验收

管理原型增加“用户与权限”“用户记录”入口，以固定合成样例及本次对话的共同记录演示：管理角色拒绝、用户暂停/恢复、角色与环境编辑、超范围授予拒绝、记录过滤、正文用途理由、短期租约、过期和访问审计。合成记录明确标记，不读取任何真实用户历史。

未来必须验证：跨租户枚举/搜索、正文租约过期、附件/事件/下载各 ACL、缓存撤权、SSE 撤销、角色自提权、并发 grants、审计失败、暂停期间在途操作及外部记录不可见。离线按钮只能帮助评审规则，不提供服务端安全证据。

## 与当前对话联动的走查补充

当前合成预览用户在用户管理中有明确对应项，管理该用户的暂停 / 恢复 / 授权修订会影响同一对话，撤权同时过滤历史标题和正文。恢复用户保留草稿和历史事实，但不复活旧批准。后台记录可显示本次对话的上下文、绑定、产物与结果版本，来源失效传播到派生内容。

本人只读计划确认权是单独的权限能力，未获权提交人须交给责任人；责任人有权审批不代表有权看全部用户正文。正文租约除到期外，在离页、角色 / 授权或来源变化时撤销；前端及时隐藏缓存，重新进入要新用途授权。自动到期由离线时钟推进用例验证，不能当作真实服务端鉴权证明。

## 每用户执行方式

用户管理增加继承角色、自动只读、逐次审批、本人确认、仅收集。角色允许自动只读与环境上限共同约束，普通用户不能用聊天更改方式；获权管理员修改须理由、CAS 和范围检查。自动检查按 policy authority 记录每次授权，未满足范围降为审批或拒绝，不能把自动模式当无限委派。执行与审批工作台详见[设计](EXECUTION-APPROVAL-RESOURCES.md)。

角色还限定可用检查流程；用户选择系统环境后，候选功能继续与环境开放流程、模型和资源依赖求交集。获准发起某流程不等于获得所有 MCP 工具或后续新增依赖；真实调用还须当前资源授权、具体计划及准入校验，见[配置到执行](USER-FLOW-AND-CONFIG.md)。

## 首次成员开通

[首次使用设计](FIRST-USE-AND-TRIAL.md)统一未加入、待开通、正常和已暂停的转换。成员列表展示待开通状态和申请用途；权限管理员明确选择范围、执行方式及理由后开通。离线演练与当前对话用户共用成员记录，不创建真实账号。申请拒绝 / 撤回、邀请领取和 SSO 仍只有设计。

## 成员模型额度设置

成员详情增加按执行连接 / Agent / 模型组合的额度设置，默认继承全局配置，仅例外成员单独设置。保存包含变更理由、权限与修订检查及确认，额度不增加模型权限。具体继承、预占与生效规则见[系统环境、执行上下文与用户额度](SYSTEM-CONTEXT-QUOTAS.md)。

## 有效权限与本轮执行摘要

成员草稿展示环境与 Agent / 模型交集，未保存不生效。记录页展示固定执行摘要；缺失历史快照显示未记录，不用当前配置补写。正文仍需用途租约，元数据不附带正文访问权。具体操作、边界与未实现项见[接入与治理完整操作设计](ACCESS-GOVERNANCE.md)。
