# 提问、执行、交付与管理排查的衔接合同

初始设计整体走查补充。用户端继续是一个对话界面；后台配置、接入、治理及详细演练按职责组织。本页把各专项设计之间的交接条件写成一条链路。

## 一份问题记录贯穿各层

| 阶段 | 接收 → 产出 | 交接必须满足 | 对话 / 管理端表现 |
| --- | --- | --- | --- |
| 用户提问 | subject、固定系统环境、消息键 → 已保存消息与 inputRevision | 服务端认证、范围过滤、同键去重；草稿不进入执行 | 用户看到已保存 / 待补充；管理员可按获准范围定位同一 conversationId |
| 上下文准备 | 输入、附件、代码、记忆、配置 → ContextManifest | 先 ACL 后检索；未解析附件只作待处理引用；来源可追溯 | 按需展开检查依据，不把文件名当已读取内容 |
| 执行准入 | 预设、Agent、运行环境、模型与 MCP 观察 → 固定 PreparationManifest | 实际能力已确认；认证、隔离、预算和工具 schema 符合；未知阻断真实启动 | 当前离线演示明确真实能力 unknown，不声称已接通 |
| 具体审批 | 固定计划、输入/上下文/接入修订 → BusinessApproval | 操作、参数、环境、哈希、前置条件、有效期及审批权匹配 | 有权者可确认本人获准的只读计划；无权者等待负责人 |
| 后台执行 | 已批准计划 → 唯一 Binding、Provider 事件、工具事实 | 不换在途拥有者；原生权限响应与资源服务复查都通过 | 用户看到处理过程，管理员看到同一 Binding / 上下文 / 外部引用 |
| 结果导入 | 证据、产物 → ResultRevision / Artifact | 导入、哈希、来源 ACL、时点和代码版本满足合同 | 先交付待验证；文件下载再次鉴权 |
| 用户验收 | 当前 resultRevision + 当前输入轮次 → 独立验证记录 | 未被新问题或新结果替代；必要证据仍有效 | 旧结果保留历史确认，不能代替当前问题的确认 |
| 管理排查 | 会话引用 → 脱敏元数据 / 有期限正文读取 | 管理范围、正文用途租约、逐次 ACL 与审计 | 可审阅事实和未知项，不替用户验收、不隐式重执行 |

平台的消息、事件、输入采用、审批、Binding、工具调用、上下文与产物都通过稳定引用关联。管理列表必须读取同一业务记录的授权投影，不能另造一套“看起来相似”的用户排查数据。

## 固定快照与当前准入分开

保存 `configurationSnapshotRevision`，表示会话 / 节点实际冻结的配置；另保存 `admissionPolicyRevision`、当前授权修订及能力观察修订，表示最近一次准入校验。管理员改名、改默认模型或连接后，不得把旧快照重新标为新配置修订，更不能悄悄改写原拥有者。

准备计划至少绑定 conversationId、inputRevision、requestedModel/presetRevision、实际采用模型观察、runtimeManifest、contextManifest、integrationSnapshot、mcpConnection/schemaHash、memory 版本、授权修订及 operationHash。新输入、模型偏好、工具清单、认证、权限或记忆依赖变化后，重新准备与审批；不能把旧批准移给新计划。

用户在执行空闲且旧执行已安全关闭时可以改变后续模型偏好。该操作使待确认卡片失效；运行中模型选择不可用。请求模型与实际采用模型分开保存，实际未知就写 unknown，不能把下拉框标签当实际模型证明。生产启动须满足正式能力准入，本轮模拟不对此提供替代证据。

## 提交人、审批人、验收人是三个责任

“用户点了允许”只有在该用户拥有此操作审批权时有效。角色只允许本人会话的限定只读确认，不包含替他人审批或写入；无权者只能把固定计划交给责任人。负责人审批界面展示目标范围和当前上下文 / 输入修订，不因其能审批就开放全部用户正文或附件。

批准后仍须执行前复查原生请求及资源策略；待确认卡片本身也有期限；离线建议窗口为 5 分钟，到期后不能由迟到点击复活，需重新准备。原生权限失效、送达未知、内层拒绝遵循[审批恢复](APPROVAL-RECOVERY.md)。负责人批准和执行完成均不能触发问题 resolved；用户验收必须绑定当前结果版本。管理员排查不提供“顺手重跑”按钮。

## 失效传播与可见性

| 变化 | 待处理 / 在途执行 | 已交付内容 |
| --- | --- | --- |
| 暂停用户 / 授权收紧 | 拒绝下一步、失效旧审批与流、取消后核查在途结果 | 历史标题、摘要和正文先过滤，不能只禁发送按钮 |
| 模型 / Agent / MCP schema 或观察变更 | 旧准备计划失效；新动作重新准入；原拥有者保留 | 不重写旧观察；已产生证据是否仍可用逐项判断 |
| 记忆撤销 / 原来源撤权 / 删除墓碑 | 禁止新增检索，含该依赖的计划重新准备 | 重新检查派生结果与产物 ACL；不可用正文隐藏，下载和验收阻断 |
| 配置仅显示名变化 | 冻结快照保留；是否重批按依赖比较策略 | 历史事实和结果版本保留，不能伪装为新配置执行 |
| 审阅租约到期 / 角色切换 / 离开审阅页 | 不影响任务执行 | 正文缓存隐藏；重新进入不能自动沿用旧租约 |

停止分派与外部动作停止不同。真实执行撤权后须发取消并核查，unknown 不释放拥有权、不换后端重放。离线定时回复可以立即停止，是因为明确没有发生外部执行；不能据此推导真实取消保证。

## 结果和文件交付

ResultDelivery 关联 resultRevision、inputRevision、contextManifest、证据引用、产物清单及独立 verification。产物记录导入状态、真实字节数、媒体类型和哈希；就绪且当前有权才提供短期内容引用。旧结果可以作为历史保留，但新问题发出后不能用旧确认按钮完成当前问题；下载历史产物仍需要其本身 ACL。

原型在对话内提供明确标记为“合成差异示例”的 CSV，固定样例的差额用确定性减法得到；它没有读取用户附件或业务系统。下载事件、上下文、结果版本和用户确认同步到本次管理员记录；示例文件不冒充真实问题结论或真实证据。

## 原型的共同记录与限制

[journey.js](../prototype/journey.js)维护同一页内的合成用户、会话投影、事件、上下文与记忆依赖，连接用户对话和管理员记录。原来的固定样例仍用于空白时评审；新产生的对话按当前管理范围出现。当前对话用户在用户管理中有明确对应项，暂停 / 恢复和权限变化会影响其后续交互；恢复不会复活旧批准。

正文租约有自动到期定时器，离页、角色切换或授权变化清除可见缓存；浏览器用时钟推进验证到期。当前一页内的事件和用户共享不是服务端事务或真实身份系统。刷新仍清空全部模拟，真实模型、ACP、MCP、附件解析、资源访问与外部副作用均未执行。
