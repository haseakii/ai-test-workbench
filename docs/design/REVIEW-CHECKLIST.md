# 评审与验收清单

本轮退出条件是“设计及离线原型可审阅”，不是业务可用。类型声明尚未与任何后端实现绑定；机器用例目录是未来两条后端的共同验收输入，不是已通过报告。

| 门槛 | 本轮交付 | 仍待证据 |
| --- | --- | --- |
| 契约 | 方法、字段、回执、错误、游标、幂等及最终排除路径 | 技术评审、适配器实现及声明编译 |
| 分层状态 | 五层转换、触发人、守卫和跨层事务 | 数据库约束、CAS/outbox、进程重启恢复 |

## 设计评审问题

1. 是否接受最终排除接纳能力不支持时保持未知并转人工，而不是自动容灾切换？
2. 是否接受原生请求失效后，即使计划未变，也保守地新建业务审批？
3. 是否接受用量未上报默认禁止新计费调用，仅保留不计费核查和停止？
4. 首链路是否固定一个系统/测试环境/流程，并将复杂编辑和受控写入保留后续？
5. 幂等/审计保留期、业务证据延迟容差、审批责任/代理规则需要在接入方案中由责任人确定。

以上是待评审事项，不阻碍本轮完成设计和原型；不据此索取资源权限或启动真实调用。

管理配置另评审[配置发布、权限及快照边界](ADMIN-CONFIGURATION.md)：修改默认项不迁移既有执行，撤权优先于旧快照，真实管理权限和具体审批权分开。

## 离线复核入口

`python scripts/check_initial_design.py` 检查链接、合同目录、转换表与构建一致性；`node docs/prototype/tests/model.test.cjs` 检查关键模拟约束；浏览器检查使用 `docs/prototype/tests/browser-check.cjs`，需要环境已有 Playwright 和 Chromium/Edge。依赖路径由运行环境提供，不写入项目。

新报告保存到 `docs/reviews/initial-design-checks/`，不覆盖历史 tests/。报告必须包含命令、时间、浏览器、源文件哈希、执行范围及未覆盖项。不得把模拟合同检查改写为真实 Provider 验收，也不重复使用历史“32 项通过”作为本轮数量。

## 完整目标的设计覆盖

按[覆盖矩阵](DESIGN-COVERAGE.md)检查 11 项需求：交互、系统、服务执行、模型、ACP、运行环境、上下文、记忆、代码、MCP、用户和记录治理。`python scripts/audit_design_scope.py` 检查章节引用；加 `--browser` 进一步匹配当前离线用例与源码摘要。真实接入和服务安全未实施，不由章节存在或模拟通过推导。

整体链路复核还须用同一 conversationId 检查[衔接合同](END-TO-END-WALKTHROUGH.md)：原问题到后台记录、冻结 / 准入修订、无权提交人等待负责人、结果 / 输入版本、文件再授权、记忆来源撤权、用户暂停及租约 / 计划到期。离线用例在 walkthrough-checks.cjs；真实外部动作仍独立验收。

新增 D12 / D13：检查[执行与审批策略及环境资源](EXECUTION-APPROVAL-RESOURCES.md)，要求用户模式不能越过角色 / 环境上限，自动决定有具体授权依据，多项目 / MCP / Skill 修订和依赖固定，拒绝不执行，多条运行按指定 Binding 停止。与下文 D14 首次使用合计 14 项设计需求映射，真实准入仍需实机验收。

日常页面额外按[列表 UI 规格](ADMIN-DAILY-UI.md)检查：首次打开可见表格，未自动打开详情；搜索 / 环境 / 状态与空状态可用；历史审批绑定原计划；示例决定不生成执行；抽屉关闭、焦点与底部动作可用。

日常操作另按[可用性走查](../reviews/USABILITY-REVIEW-20261025.md)检查完整路径：配置错误可定位、目录可返回、草稿未提前生效、已有授权显示完整、审批条件与意见固定、搜索与窄屏动作明确。

按[用户到执行](USER-FLOW-AND-CONFIG.md)复核流程、环境、角色、模型和工具依赖；候选配置与真实准入分开，禁止用同名工具替代另一连接、禁止把未知目标默认执行为报表核对。

## 首次使用

从设计资料打开首次开通演练，未加入 / 待开通时不能选择环境或提交检查；权限管理员按申请授予环境与执行方式，再按负责人审批完成同一问题的交付和用户验证。验证记录见 `onboarding-checks.cjs`；首次部署、真实身份、邀请领取、拒绝 / 撤回与数据库事务仍未运行。

## 任务标题

首次提问获得安全短标题，附件或未知问题保留待补充名称；补充后最多细化一次。手动重命名后检查历史、任务、审批和记录同名，既有批准 / 结果验收不受影响；取消不丢消息草稿，手工标题不被自动覆盖。检查敏感格式、长标题、同名不同编号、移动端与撤权，真实语义概括和服务端同步另验。

## 接入治理管理链路

按[接入治理操作设计](ACCESS-GOVERNANCE.md)从新增连接开始核对：模拟发现不变真实准入、创建预设带入所属连接、环境与角色均需显式授权、停用默认项不静默换 Agent、运行配置与上下文策略进入固定快照、MCP 变化重新确认、个人记忆所有者、成员草稿有效范围、记录正文租约和窄屏操作。另检查接入方式 / Agent 身份变更后旧预设不能使用旧额度键执行新身份。

连续用例 `complete-journey-checks.cjs` 要求从新增执行及资源配置到成员开通、审批、交付和审阅保持同一浏览器状态，核对实际选择的配置引用、额度键、计划、Binding、标题和结果修订；不能以预置默认配置的分段用例代替。其通过仍不证明部署、SSO 或真实 Provider。
