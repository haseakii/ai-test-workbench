# 执行环境、系统接入与代码读取

初始设计评审稿。本页细化执行所需环境与资源，不创建容器、工作区、数据库连接或真实代码镜像。

## 三种环境分别建模

业务环境是用户选择的“订单系统 / 测试环境”，执行环境是 Agent 所在的受控宿主，代码快照是特定部署对应的不可变来源。三者分别为 Environment、ExecutionEnvironmentProfile、RepositorySnapshot，以明确引用关联，不能把业务测试环境名称当 OS 沙箱。

运行档案至少保存：runtime/image digest、平台与架构、Agent 制品摘要、执行身份引用、cwd 模板、只读/临时写挂载、网络目的地允许列表、CPU/内存/时长/并发/文件配额、进程树管理、日志脱敏、销毁与保留规则。默认无任意外网、无生产写入、无宿主用户目录、无 Docker socket 和 SSH Agent 透传。Windows Job Object / Linux cgroup 等只负责部分进程资源限制；实际隔离方案需另验收，不把它们单独称为完整沙箱。

环境状态：draft → validating → ready → draining → retired，任何边界验证失败进入 blocked。只有 ready 且观察未过期才分配；draining 不接新执行，旧执行先取消并核查。worker lease、ownershipEpoch 和固定 Binding 一起校验；租约过期不能授权另一 worker 重放原副作用。

## 系统接入合同

| 来源 | 配置引用与边界 | 每份证据必须记录 |
| --- | --- | --- |
| 代码 | repositoryId、受控镜像、部署 commit、允许路径、排除路径、读取限额 | repo/commit/path/行区间、blobHash、读取时点 |
| 数据库 / 报表 | resourceRef、只读执行身份、允许数据集/模板、行数/时长、快照策略 | 参数哈希、业务区间、时区、asOf/watermark、截断 |
| 日志 | 索引/服务允许列表、时间范围、脱敏规则和条数上限 | 服务/版本、事件时点、关联 ID、检索范围、覆盖率 |
| 系统 API | 固定服务目录、方法路径允许列表、认证引用、参数 schema | 请求业务定位、响应哈希、服务版本、是否缓存 |
| 附件 | 会话内对象 ID、MIME、大小、哈希、隔离解析状态 | 原文件哈希、解析器版本、页/单元格/定位与截断 |

连接验证分为配置合法、网络可达、认证、最小只读操作、证据一致性和资源强制边界六步；连通不等于准入。探测须是明确的低成本无副作用模板，用户资料不参与测试。当前只能演示验证清单，不运行这些探测。

数据库使用专用最小只读角色，受控模板/参数绑定和资源层规则共同限制，禁止自由任意 SQL、动态拼接、DDL、写存储过程、文件/网络外带及跨库扩权。只读事务本身不能保证任意函数无副作用。查询取消和超时由数据服务记录事实，过期查询不得启动替代操作；结果超限返回截断证据，不声称全量核对。

## 代码读取流程

1. 平台配置受控 repositoryId，服务账号仅可读取该仓库。用户不能输入任意 URL 拉取，禁止执行仓库 hook、安装脚本、构建脚本、子模块脚本或 `.gitconfig` 外部命令。
2. 从部署登记取得实际 commit，与用户问题时点匹配。找不到部署 commit 时 codeCommit/deployedCommit 保持未知，只能给有边界的推测；不可用最新 main 冒充现场代码。
3. 镜像同步和索引任务在独立受限账户执行，按仓库、commit、可见路径和 ACL 修订分区；不共享不同租户的可见索引结果。
4. 解析符号链接、junction、硬链接别名、大小写与路径分隔；规范化后验证真实路径仍在授权根内，防检查后替换。链接逃逸、不可固定路径或大文件超限时拒绝。避免把私有宿主路径写进错误文案。
5. 搜索先按 ACL 和快照过滤，再排名；逐次读取重新鉴权。内容引用记录文件哈希和行号，代码片段只在获准材料中出现。
6. 只读挂载优先。worktree 仅是 Git 工作方式，不是隔离。若必须复制源码到执行区，禁止凭据与敏感排除路径，记录导入清单及摘要；执行结束按保留策略清理并核查。

分支和标签只是解析输入，固定后用 commit/object hash。子模块与 LFS 分别登记来源与内容摘要，未导入即明确缺失；不自动跨仓库取数。代码索引过期、snapshot 不匹配或权限变更时失效，不沿用缓存片段形成确定根因。

## 文件与网络出口

附件原件进入隔离区后才可扫描/解压/解析；限制压缩比、嵌套深度、总字节、超时和页数。仅解析内容，不运行 Office 宏、HTML 脚本、PDF 动作或内嵌命令。输出结构带可信度和缺页信息；失败保留原哈希与错误。

网关依据实际执行身份注入最小短期资源凭证，凭证不进入模型上下文。网络只放行批准的模型/工具/资源服务目的地，校验重定向和 DNS 变化，拒绝任意内网地址及云元数据端点；指定内网资源必须单独登记允许范围，不能一概放开整个网段。

产物从执行区导入平台对象存储，先核验来源、格式、大小、哈希与恶意内容，再分配可下载引用。临时写目录仅存检查计算与输出，不拥有业务代码或数据库写权限。

## 隔离与恢复验收

服务边界草案：`POST /admin/runtime-profiles/{id}/validate` 对固定档案生成隔离检查任务与证据引用；`POST /repository-snapshots` 仅接受已登记 repositoryId 和受限 ref，返回固定 commit 的导入任务；`POST /code-search` 接受 snapshotId、query、限定路径、limit；`GET /code-blobs/{id}` 接受行区间并重检 ACL。搜索和读取不能执行仓库脚本，返回 hash、实际范围和截断标记。数据/日志也通过预登记资源与模板执行，客户端不提交任意连接串或执行身份。所有任务遵循服务执行的命令幂等与事件审计，真实调用尚未实现。

未来需验证越界路径、链接逃逸、只读文件写入、任意网络、环境变量窃取、终端绕过、超额子进程、OOM、worker 崩溃、清理失败和代码版本不匹配。资源服务记录拒绝与审计，宿主崩溃时仍核查在途查询与 MCP 动作。正式上线前必须有实际隔离证据；本轮仅有策略和拒绝场景的离线预检。
