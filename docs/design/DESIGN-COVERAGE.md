本轮目标是把前台交互、后台执行、系统与模型 / ACP / MCP 接入、运行环境、上下文记忆及管理治理设计完整。用户端保留已认可的单一对话，后台配置和治理按职责分组。以下是设计交付的逐项覆盖，不是生产功能或真实接入验收清单已通过。

## 原型的信息架构

用户端一个对话入口。管理端基础配置四项（环境归入系统，模型预设归入 Agent 接入，兼容详情链接保留），另有执行与审批两项工作台、接入与治理五项：Agent 与模型接入、运行配置、上下文与记忆、用户与权限、用户记录。原有七个详细视图继续作为次要契约和恢复演练。另有首次开通演练，当前共 22 个可检查视图，包含用户、配置、治理与设计演练；数量不等于首条业务链路必须实现全部页面。

基础配置的应用只改变本地已应用配置；接入方案是未准入草稿；用户与记录包含固定合成资料，以及本次对话共享的合成记录。它们用于评审边界，没有伪造真实服务、连接、用户记录或权限系统。统一正式配置发布、权威执行和受控资源在服务设计中定义，仍待新的实施任务。

## 审视结论与后续门槛

完整设计已明确业务与执行归属、接口输入输出、角色和资源范围、配置与运行快照、上下文和记忆来源、协议兼容、错误/未知/取消恢复，以及管理员内容访问约束。具体数据库/IdP/隔离实现、模型供应商、真实限额和业务留存数值在实施时由责任人选择和验证；本轮给出责任、决策条件和失败路径，不伪造选择已批准。

本轮设计退出证据为：上述文档与边界声明可读取；需求映射无缺项；原型代表路径和故障可交互；当前源文件与报告哈希匹配；历史原稿保留。另见[检查报告](../reviews/initial-design-checks/README.md)。

生产门槛另行要求：真实身份 / ACL、秘密管理、协议互通、模型实际采用、进程和资源隔离、代码/数据证据正确性、上下文与记忆删除、事务与事件恢复、费用强制限制，以及总控关闭时 ACP 基础链路。它们未执行，不属于本轮“完善设计”完成证明。
