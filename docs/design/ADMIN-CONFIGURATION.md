# 管理端：为对话提供配置

状态：初始设计评审稿，仅离线原型。用户已认可当前对话界面，要求系统、环境、模型和权限由后台配置。本页承接该定位，不建立新的产品版本，不接入真实资源。

## 信息架构与职责

另设执行管理与审批管理两个主入口。管理端以系统设置（内含环境）、权限配置、资源目录、检查流程四项作为基础配置，另按当前完整设计目标增加Agent 与模型接入、运行配置、上下文与记忆、用户与权限、用户记录五项。编辑区旁提供“用户端预览”，帮助管理员判断配置会让用户看到哪些选项。用户端继续保留系统、环境和模型选择，但不提供连接、角色策略或资源配置表单。

执行连接诊断、ExecutionProvider、五层状态及审批恢复放在次要的“设计与契约评审 / 审批恢复演练”入口。它们仍是独立合成演练，不能冒充当前用户对话的真实运行记录。代码 / MCP / Skill 目录与环境关联已纳入；复杂工作流编辑、可执行 Skill 发布引擎、知识库和复杂协作暂缓，不重建完整后台门户。

| 页面 | 主要对象与字段 | 本轮交互 | 校验与影响 |
| --- | --- | --- | --- |
| 系统设置 | 稳定 ID、显示名称、负责团队、用途、启用、常用问题 | 选择 / 新增合成记录、编辑、启停、选择快捷问题 | 名称必填且唯一、负责团队必填；快捷问题只填入用户输入框 |
| 系统设置 → 环境 | 稳定 ID、所属系统、名称、启用、默认模型、只读资源范围 | 选择 / 新增、所属系统与名称编辑、默认模型选择、启停 | 同系统环境名称唯一；默认模型须启用且对获该环境权限的角色可用 |
| Agent 接入 → 模型预设 | 稳定预设 ID、显示名称、执行连接、Agent、实际能力、启用 | 选择 / 新增预设、显示名称与连接映射、启停 | 显示名唯一；真实模型、实际能力始终为未知；切换连接只改变草稿映射 |
| 权限配置 | 角色、允许环境、允许模型、资料访问、审批责任、调用和并发上限 | 两个合成角色间切换、授权范围编辑、预览身份 | 默认拒绝；无交集显示空状态；数量输入检查整数范围；禁止写入 |

新增系统、环境、模型均默认停用。它们还需补充配置、授权和预览后应用，不自动授予所有用户。原型用停用代替删除；正式产品的删除必须检查引用和保留期。稳定 ID 与显示名称分离，名称变化不能改变历史归属。

环境中的代码项目地址、MCP 和 Skill 已可通过资源目录自定义并关联；数据库、日志、附件及产物的真实权限仍按资源服务设计处理。本轮不允许填写凭据、真实连接串、Token 或客户数据；正式资源映射必须指向受控资源服务和真实执行身份，绝不能靠提示词、前端勾选框或 worktree 目录代替权限限制。

日常处理页面采用列表和按需详情，见[日常管理 UI](ADMIN-DAILY-UI.md)；配置编辑与技术诊断不再混入审批首页。

## 草稿、预览与应用

1. 编辑即时保留在本页内存草稿，跨配置管理页面切换仍保留；不直接改变用户可选项。
2. 预览按合成角色展示草稿的系统、环境、模型及资料访问范围。切换预览身份只改变离线评审身份，不是登录或角色授权。
3. “预览并应用”先检查重复名、缺少负责人、无效默认模型、角色与默认模型冲突及数值范围。失败保留输入，在页面显示原因。
4. 默认只发布当前对象，预览展示对象及依赖影响；需要跨对象一起发布时，显式选择变更集。未选草稿既不发布也不丢弃。取消 / Escape 保留草稿并返回触发按钮；放弃默认只恢复当前对象。依赖不完整时拒绝所选变更集，不自动携带其他页面的草稿。
5. 应用后产生配置修订号、合成操作人、时间与修改对象记录。修订号只标识配置快照，不是产品版本。刷新清空改动和审计记录，正式持久化尚未实现。

发布记录在正式实现中还需存储字段级前后值、变更理由、操作者授权及复核责任。需以基础修订号做 CAS，原子更新配置快照和审计 / outbox；过期草稿冲突时返回差异，不覆盖他人修改。原型是单人内存状态，不提供并发、服务端事务或审计不可篡改证明。

## 前后台映射与既有会话

用户新会话的可选项取自已应用配置与当前身份授权的交集：启用系统 → 启用且获准的环境 → 启用且获准的模型预设。环境定义默认模型，系统定义快捷问题。空交集明确提示无可用检查范围并禁止发送，不回退到未授权系统或模型。

首次发送记录稳定对象 ID 与配置快照，固定系统、环境及当时的执行连接映射。管理员之后改名、改默认模型或连接映射，不改写该快照，不静默迁移正在运行的执行。后端内部重试仍由唯一执行拥有者负责；新默认值只影响后续新建会话 / 执行单元。

停用或撤销授权优先于历史快照。在发送、原生权限响应和实际操作前重新核查当前授权；过期或撤权阻止下一步，保留原问题、材料及原拥有者，不自动换后端。离线原型演示停止范围之外的后续回复、禁发、保留草稿；不声称已能撤销真实正在执行的动作。真实在途执行按[执行契约](EXECUTION-PROVIDER.md)发取消并核查回执，未知效果不得重复执行。

当前原型按本计划实际引用的系统环境、模型、流程、资源、授权及额度生成语义依赖标记。无关系统或纯展示名称不使待确认卡片失效；相关说明 / 工具 / 代码范围变更需重新准备并确认。正式服务采用依赖修订与规范化哈希并重新鉴权；字符串标记仅是离线演示。预设修改不冒充模型发现，在途 Binding 保留原快照，实际撤权仍阻断后续操作。

## 权限与审批责任

配置权限、资源使用权限与具体操作审批分开。配置管理员维护策略，不自动具有查看所有问题材料或批准具体操作的权利。正式角色建议分为配置管理员、测试人员、审批责任人和审计读者；本原型只用“测试人员 / 协作成员”两种合成使用身份预览，对配置管理入口不实现登录鉴权。

| 对象 / 操作 | 正式约束 | 原型覆盖 |
| --- | --- | --- |
| 系统 / 环境 / 模型 | 每次读取和执行校验身份、对象范围、配置与观察有效期 | 可选项过滤、空状态、下一步禁发及快照保留 |
| 附件上传 / 读取 | 两个独立动作分别校验本会话 ACL、大小、类型、保留期与安全处理 | 仅“添加附件”开关限制本地文件名记录，无内容读取 |
| 历史搜索 / 会话读取 | 查询和逐条读取均校验，不泄漏未授权标题、计数或摘要 | 合成身份隔离最近对话；历史关闭隐藏其他会话入口 |
| 事件 | 独立读取权限；敏感工具参数脱敏 | 配置及草稿效果预览，不接通真实事件 |
| 产物 / 下载 | 元数据、内容、导出和接管包分别校验；失效链接重新授权 | 配置及草稿效果预览；不增加用户端真实下载 |
| 具体操作审批 | 操作、参数、环境、哈希、前置条件、责任人、有效期均绑定 | 简化确认卡片与独立审批恢复演练 |
| 调用 / 并发 / 费用 | 可强制数量限制与估算 / 未上报费用分账，子任务共享预算 | 配置数值与校验；不实施真实限流或计费 |

用户对话中的“允许本次检查”只有在服务端确认此用户有该操作审批权时才能成为有效批准；否则应显示等待责任人批准。模型开关和管理员应用配置都不是具体操作批准，外层批准也不能绕过受控资源服务的内层策略。

## 原型构成与验收范围

[configuration.js](../prototype/configuration.js)保存合成配置、草稿、角色预览与快照；[admin.js](../prototype/admin.js)实现四页配置交互；[chat.js](../prototype/chat.js)消费已应用的演示配置。三者仅在同一离线 HTML 的内存中运行，不是业务模块或生产 SDK。扩展的接入与治理演示见 [service-design.js](../prototype/service-design.js)，有固定合成资料、共享当前对话记录和接入方案草稿，不被四项配置的“应用”发布，也不会绕过真实准入。正式统一发布边界见下节。

验收关注：编辑未应用不影响对话、跨页面草稿不串字段、预览取消、失败保留输入、默认模型与权限冲突、身份范围、映射变更不改旧快照、撤权阻断、待确认卡片失效、空配置、审计和刷新边界。旧用户对话交互与合同恢复演练同时回归。完整认证授权、并发发布、资料下载 ACL、真实能力发现、硬预算和后端安全均留待明确授权的实施任务。

## 接入与治理的统一发布边界

接入档案、运行与上下文策略应使用独立对象修订和同一兼容性验证，只有真实验证达到准入后才能被模型预设 / 环境引用。提交配置需冻结全部依赖修订，CAS 原子发布快照并写审计；不能只发布显示名称而丢失背后权限、模型观察或运行策略。原型的基础配置应用、接入方案草稿、合成用户变更和正文租约分别演示其交互，不宣称已连成生产配置服务。详见[服务执行](SERVICE-EXECUTION.md)、[模型与 ACP](MODEL-ACP-ACCESS.md)、[用户治理](USER-GOVERNANCE.md)。

整体走查后，当前用户、会话记录和记忆依赖由 [journey.js](../prototype/journey.js) 在同一离线页内关联。四项配置的应用、演示用户变更、记忆审核和正文租约仍不是生产配置事务；其衔接和失效传播见[衔接合同](END-TO-END-WALKTHROUGH.md)。

## 用户提交后的管理与扩展资源

[执行、审批与资源设计](EXECUTION-APPROVAL-RESOURCES.md)补充执行管理、审批管理、用户四种执行方式、角色 / 环境策略交集，以及可新增的代码项目、HTTP / stdio MCP 和内联 / 仓库 / 包来源 Skill。环境关联多个项目与 ref 覆盖，按计划固定修订。真实接入准入未知时仍不能执行；自动只读仅是本地演示。

## 配置操作便利性

应用 / 放弃操作栏随长表单滚动保持可见；无改动时禁用。跨页面的错误按对象与字段列出“前往修正”，点击后定位对应页面、目录类型和输入，不清除其他草稿。错误修复后重新校验，正式服务基于已发布状态叠加所选变更集，重新校验依赖、授权和各对象 expectedRevision。

环境配置提供代码项目、MCP 与 Skill 的独立目录入口和返回原环境入口，两端共用尚未应用的配置草稿。当前原型没有目录检索、持久化、多管理员并发与真实服务错误，这些仍是后续实现门槛。

## 检查流程与用户入口

采用历史原型清楚的流程列表 / 表单，维护三类固定检查模板；配置检查目标、需要的只读工具、Skill 和代码要求。环境开放哪些流程，角色允许哪些流程，决定用户的候选范围；工具必须用连接 ID 与工具名定位。此页不提供自由流程引擎。完整链路见[用户操作与配置](USER-FLOW-AND-CONFIG.md)。

## 代码来源与凭据表单

资源目录 → 代码项目提供“在线 Git 仓库 / 本地文件目录”。在线 Git 默认 GitLab，填写仓库、ref、读取路径及认证；Access Token 用密码框录入，当前原型仅演示清空输入并生成凭据引用。本地目录填写执行节点、绝对路径和相对读取范围，不显示分支或 Token。环境仍引用同一个项目目录；切换来源与凭据更新需应用配置，不改变旧执行快照。详见[代码来源](RUNTIME-RESOURCES.md#代码项目来源本地目录与在线-git)和[Token 配置](EXECUTION-APPROVAL-RESOURCES.md#gitlab-access-token-配置)。

## 系统归属、背景与按模型额度

环境从系统详情进入，不再占用主菜单。系统与项目说明、环境口径进入带来源的本轮背景清单，资源 ID、版本和权限由结构化配置约束。权限页提供全局默认额度，成员设置可按执行连接 / Agent / 模型组合单独覆盖或恢复继承。规则与执行事务见[系统环境、执行上下文与用户额度](SYSTEM-CONTEXT-QUOTAS.md)。

## 接入与治理统一操作路径

Agent / 模型入口合并，MCP 保留独立目录注册，环境显式绑定可用模型组合、默认预设及上下文策略。连接与运行配置从列表进入表单，协议与故障演练折叠。配置发布与模拟发现分离，真实准入仍未知。各页职责、操作及失败恢复见[接入与治理完整操作设计](ACCESS-GOVERNANCE.md)。
