# 上下文、会话与记忆

初始设计评审稿。目标是持续排查而不丢失来源和权限；不是把全部历史、整仓代码或用户资料自动喂给模型。

## 分层数据与信任

| 层 | 范围 / 生命周期 | 能否作为已证实事实 |
| --- | --- | --- |
| 原始问题材料 | 当前会话消息、附件和用户给定条件，按会话 ACL 与保留期 | 用户陈述，不自动等同系统证据 |
| 本轮上下文包 | 固定运行选择的消息、代码、证据、Skill 与记忆版本 | 每项标来源和可信等级，摘要不能升级证据 |
| Provider session | 执行拥有者的原生会话与内部压缩 | 非平台权威业务记录；恢复需能力及授权检查 |
| 会话摘要 | 有原消息/证据引用和压缩器版本的可重建投影 | 只是摘要，冲突回到原始材料 |
| 长期记忆 | 审核后的个人或特定系统环境知识，独立范围和期限 | 方法/假设与事实区分；不能替代当前取证 |

指令优先级来自平台和获准工作流，用户问题设定目标。仓库注释、网页、日志、MCP 返回、附件及记忆都作为不可信数据引用，不能改变权限或指令优先级。项目方法文件仅在固定来源、哈希和已批准 Skill 范围内提供方法约束，也不能授予资源访问权。

## 上下文组装合同

ContextManifest 包含 tenant/subject/conversation/run、配置与授权修订、system/environment、部署与代码 commit、模型观察、tokenizer/估计方式、总预算和输出预留、各材料引用/哈希/来源/ACL/时点/截断/选择理由、Skill 修订、使用的记忆版本、摘要版本、排除原因及 manifestHash。只存引用与必要摘要，不复制秘密。

组装顺序：当前策略和固定操作合同 → 本轮目标及明确条件 → 当前直接材料 → 与现场版本匹配的证据与代码片段 → 带来源的近期会话摘要 → 经授权且适用的记忆。先做租户/用户/环境/有效期/来源 ACL 过滤，再检索、排序和裁剪；发模型前逐项复查，缓存命中不跳过授权。

token 预算先预留输出及系统/工具协议开销，再分配给材料；预算依据实际模型已确认窗口。支持确切 tokenizer 时记录版本，否则记录估算和安全余量，无法保证容纳则缩小输入或提问。不能删除必要权限、操作计划或矛盾证据来让提示词塞进去。图片、表格和文件有单独字节/页数与模型支持限制。

超限时依次删低相关重复片段、减少窗口、生成可追溯摘要；必要证据仍超限则转分段检查并明确覆盖范围，或阻断。模型变化需要重新组装并冻结新清单，不把旧模型的预算换算直接复用。

## 连续对话和恢复

首次发送固定系统、环境和执行上下文。运行中新增消息区分“尚未提交”“排队补充”“已采用”；只有 Provider 回执可声称当前动作采用。改变检查范围或材料哈希须新计划和审批，不通过追加 prompt 偷改已批操作。

压缩生成新的 summaryRevision，记录原消息区间、未摘要冲突和原证据引用；不覆盖原记录。恢复时检查授权、配置依赖、上下文摘要与 Provider session 仍有效；必要时重新检索当前获准材料。不能以平台有摘要为理由在另一个后端重放未决执行。

Agent 自带用户目录记忆、历史会话、项目插件与全局指令必须隔离到单租户受控空间或关闭；无法证明不会混入其他用户资料的 Agent 不准入敏感环境。平台不能靠空 prompt 声称清除了执行器私有状态。

## 记忆生命周期

默认只保留业务会话记录，不自动生成跨会话长期记忆。个人记忆须用户选择保存；系统/环境共享记忆须有知识维护者审核。候选来源必须是获准结果和明确引用，错误根因、模型猜测、未验证结论不得自动发布为事实。

状态：candidate → reviewed → active → expired / revoked → deletion_pending → deleted；rejected 保留审核事实但不检索正文。更新创建新版本并明确替代关系，不就地改写曾用于结论的版本。

MemoryItem 保存 scope（个人或特定系统环境）、owner、sourceRefs、sourceHashes、内容类型（方法/事实/假设）、适用代码范围、有效期、审核者、revision、ACL、敏感等级、supersedes 和删除状态。暂不做组织全域自动共享。读取要同时满足当前身份、记忆 ACL、原始来源 ACL 和环境版本；来源撤权即使记忆自身仍 active 也不可检索。

禁止保存凭据、完整客户原数据、隐藏思维链、一次性批准、临时下载链接、未脱敏日志与越权内容。人工“保存记忆”也不能绕过这些限制。冲突记忆同时标冲突并回到当前证据，不让高点击或新时间戳自动覆盖事实。

## 保留、删除与追踪

管理 API 草案：`POST /context-manifests/preview` 返回按当前授权过滤的材料清单与排除理由，不发模型；执行启动时服务端重新生成并固定清单。`POST /memory-candidates` 引用获准材料提出候选；`POST /memory-items/{id}/review` 记录审核与预期修订；`POST /memory-items/{id}/activate` 只允许 reviewed 且来源仍有效；`POST /memory-items/{id}/revoke` 立即停止检索；`DELETE /memory-items/{id}` 返回 deletion_pending 与清理 jobRef，`GET /deletion-jobs/{id}` 逐项显示回执。每步分别校验维护者范围、原来源 ACL、CAS 与审计；不存在“写入任意全局记忆”入口。

待评审初值：对话/附件保留 30 天、短期内容访问租约 5 分钟、记忆候选 7 天未审自动过期、共享记忆 30 天复审；这些是建议配置，不是已获业务批准的合规承诺。法律保全等真实要求需独立策略，保留期间也不开放所有管理员读取。

删除立即打墓碑并禁止新检索，再清除正文、摘要、向量索引、缓存、派生产物和外部副本引用，记录各处理回执。索引删除未确认时状态保持 deletion_pending，不能显示已完全删除。Provider 的外部会话保留与供应商留存不能由本地删除代表；不支持删除时明确受限并按接入策略停用/隔离。

审计记录“本轮用了哪些材料和记忆版本、为何选中、何时失效”，不记录秘密或原始思维链。用户可在对话中按需展开“检查依据 / 已使用材料”，管理员需额外授权才看来源正文。原型的上下文清单和记忆条目均为合成样例；没有真实检索、向量库或长期保存。

## 依赖修订与派生结果的走查补充

上下文清单同时记录冻结配置、当前准入 / 授权修订、inputRevision、模型请求及实际观察、工具 schema、记忆版本与原来源状态。候选、未审核、环境不匹配或来源撤权的记忆不得组装；附件只有文件名时保持未解析。记忆 / 原来源失效要使未执行计划重新准备，派生结果、文件与管理员缓存重新授权，不能仅从下轮检索排除而继续提供失效正文。

[共同离线记录](../prototype/journey.js)将符合条件的合成记忆引用放入本次上下文，并演示来源撤权后的结果隐藏与禁验收 / 下载。记忆策略的即时变化仅用于该离线演示，正式策略仍需按配置服务发布和审核。
