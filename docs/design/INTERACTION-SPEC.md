# 初始交互规格

状态：设计评审稿。[当前离线原型](../prototype/index.html)默认打开单一对话工作台。用户定位是“普通模型对话，加上系统、环境和检查问题的快捷选择”。历史 v0.2 原稿保留，当前不另分产品版本。

## 用户端：一个对话界面

左侧只放新对话和最近对话，主体为消息流及底部输入框。空会话显示“今天想检查什么？”，提供核对报表差异、排查接口异常、分析错误日志三个快捷问题。快捷问题填入输入框，允许修改后再发送，不自动发起执行。

系统和环境紧贴输入框，可选环境随系统变化。初始合成配置包含订单、支付、报表三个系统及少量测试环境；由后台配置并按预览身份过滤，不是已接入清单。首次发送固定当前会话的系统和环境，改范围需新建会话，旧会话保留。正式产品只展示当前用户有权访问且已配置的选项，不把可见选择等同于资源授权。

输入区支持自由文本、附件入口和模型选择。当前两个模型标签都是演示预设，不代表真实发现能力；选项只影响下一条消息的模拟记录，生成期间不可切换。正式产品的实际模型来自执行器发现和策略确认；已开始执行的绑定不因用户改变后续偏好而变化。

附件在本轮只记录文件名和大小，不读取内容、不上传、不解析。可移除待发送附件，空文本但有附件也可发送。正式产品的附件上传、读取和下载逐项授权，失败必须保留输入与错误，不冒充解析成功。

## 在对话内完成检查

| 时机 | 用户看到的内容 | 原型动作 |
| --- | --- | --- |
| 首次提问 | 用户消息与助手追问 | 提醒补发生时间、预期结果、实际现象 |
| 补充条件 | 一张简洁的检查范围卡片 | 展示系统、环境、只读范围，允许或暂不允许 |
| 修改待确认内容 | 旧卡片标记被替代，新范围重新确认 | 旧卡片不能继续批准 |
| 拒绝检查 | 暂停说明，可继续补充 | 不生成完成结果 |
| 检查完成 | 对话内结论，仍待用户验证 | 合成建议；不伪造真实查询、证据或计算文件 |
| 验证结果 | “问题已解决 / 继续排查” | 明确用户确认；继续排查保留旧消息 |
| 生成期间 | 回复提示与停止按钮 | 可停止当前定时模拟，阻止延迟回复再出现 |

正式审批仍必须绑定具体操作、参数、环境、计划哈希、前置条件和期限；用户卡片可用自然语言摘要及可展开详情，不要求用户手工操作这些合同字段。当前简化卡片只是交互示例，不能直接用作真实审批 payload。实际等待、过期、重新授权与送达未知遵循[审批恢复路径](APPROVAL-RECOVERY.md)。批准不代表已经执行；Agent 完成不代表用户已确认解决。

正式检查遇到断线或结果未知，聊天中应说明“正在核查原检查，请稍候”并提供接管入口，不引导用户换后端重做。证据、文件和错误按需展开；完整诊断留给管理人员。用户不需要进入流程编辑器、绑定页或状态表才能处理问题。

## 管理配置与次要契约演练

用户已认可当前对话形式。管理端按[配置设计](ADMIN-CONFIGURATION.md)集中维护系统、环境、模型和权限；用户仍在输入区选择获准选项。管理草稿经预览和应用后影响新会话，旧会话保留配置快照；停用或撤权阻止后续检查。

原有详细视图从管理端次要的“设计与契约评审 / 审批恢复演练”入口进入。它们使用独立的合成状态，**不是当前对话的真实运行详情**。用户会话与演练不互相写入。正式管理端须有独立角色和访问控制，本轮入口隐藏不构成鉴权。

| 评审视图 | 用途 |
| --- | --- |
| 闭环演练、结果与验证 | 评审模拟状态及合成文件下载，不是用户流程导航 |
| 执行连接 | 连接 / Agent / 模型能力、未知能力及下次默认后端 |
| 运行与绑定 | 单一拥有者、原提交核查、最终封闭、取消确认 |
| 审批与恢复 | 决定、送达、动作分层，过期、新请求、重新批准 |
| 契约与状态 | 正式方法及五层状态转换 |
| 异常与接管 | 能力不足、用量未知、证据冲突、人工接管 |

管理演练保留原有接纳未知、断连、not_found 不释放占用、取消与完成竞态、送达未知不重发、内层拒绝、预算未知阻断及文件完整性门禁。平台管理和总控后端职责不因界面简化改变。

## 输入、持久性与验证边界

Enter 发送，Shift+Enter 换行，输入法组合期间不发送。空输入禁发；快捷问题聚焦输入框。发送期间可编辑下一条草稿，也可新建或切换会话；导航只改变视图，不发取消命令。切换保留每个会话的草稿、附件元数据、系统环境、消息和事件游标。在途任务按后台状态继续，侧栏显示处理中 / 排队 / 待审批；返回时恢复进度。新增执行受用户跨会话并发与队列限制，不通过禁止导航限流；停止按钮只作用于明确选中的运行。窄屏通过顶部新对话和历史选择继续使用。

消息、附件名和会话标题作为纯文本转义；消息流具有可读标签。管理页重置仍用原生 dialog，Escape 返回触发按钮。全局不使用 localStorage；刷新清空模拟记录。无服务端会话、真实模型、持久化或业务资源，所有回复由本地脚本生成。

检查包括默认对话入口、系统环境联动、快捷问题、附件元数据、文本转义、范围固定、内联授权/确认、停止回复、历史与草稿、移动端，以及原有管理演练。真实 Provider、完整无障碍、附件解析和用户问题解决率仍未验收。

## 接入与用户治理扩展

管理端补充五项设计入口：Agent 与模型接入、运行配置、上下文与记忆、用户与权限、用户记录。其交互见[完整需求覆盖](DESIGN-COVERAGE.md)，字段和拒绝路径分别在对应设计文档中定义。接入方案支持离线配置发布与合成发现；真实能力未验证不能进入真实执行；用户和记录使用固定合成样例，并关联本次离线对话，不读取任何真实用户历史。

记录列表先过滤管理范围；正文需理由及短期用途租约，过期或管理角色切换隐藏内容，下载另鉴权。用户变更先预览理由和影响，再确认，超范围与自提权拒绝。接入、运行与上下文策略不增加用户端必经页面。

## 整体走查后的交互规则

模型切换或新增材料使待确认计划失效；输入模型只表示请求，不伪造实际模型。未获本人只读审批权时，卡片显示“请负责人确认”，后台责任人对固定计划审批后才推进合成执行。结果按输入及结果版本确认，对话内可下载明确标记的合成差异示例，来源或下载权限失效即禁用。

当前预览用户可在后台对应管理，暂停禁发并隐藏不可访问历史，恢复保留草稿但不恢复批准。后台能审阅同一对话的记录与上下文引用；正文租约自动到期及离页后清理。参见[衔接合同](END-TO-END-WALKTHROUGH.md)。

## 执行与审批工作台、资源目录

用户管理可为每位用户继承或指定自动只读、逐次审批、本人确认、仅收集。角色允许范围与环境上限共同决定有效方式；自动只读只推进合成检查，实际能力仍未知。执行管理聚合用户提交并展开历次节点，审批管理处理固定计划的待办和历史，批准不代用户验收。

环境配置增加多代码项目 / 请求 ref、可用 MCP、可用 Skill 与策略上限。资源目录支持自定义项目地址、工具端点 / 受信启动模板、方法内容 / 来源 / 版本及依赖；草稿经校验应用，新计划采用新修订，旧执行快照不改写。详见[完整设计](EXECUTION-APPROVAL-RESOURCES.md)。

## 对照历史原型后的用户端取舍

用户以对话发起和持续补充，标题与历史显示业务状态；系统环境和已配置检查范围随当前权限更新。“问题信息”按需展示本轮范围、处理进度和结果文件，关闭回到原入口；不展示 Binding、权限桥或其他用户正文。输入不明确或缺少已发布流程依赖时说明原因，没有批准卡或执行。实际方案比较和配置对应见[主线设计](USER-FLOW-AND-CONFIG.md)。

## 任务自动命名与手动重命名

任务标题是问题会话的显示名称。用户无需先填标题；最近对话、对话标题、任务中心、审批列表和用户记录使用同一 conversationId 的当前标题，不各自维护副本。标题允许重复，靠稳定编号和环境 / 用户 / 时间区分。状态与系统环境单独展示，不拼进名称。

| 时机 | 行为 |
| --- | --- |
| 尚未提交 | 显示“新对话” |
| 首次提问 | 根据用户的问题概括短标题，建议 8–20 字；例如金额数字很多的提问概括为“德国订单报表金额差异” |
| 信息不足 / 只有附件 | 显示“问题待补充”或“附件问题待补充”；不把文件名当标题或假装已解析附件 |
| 补齐必要信息 | 若之前名称仍笼统，可以自动完善一次；已有明确标题不随每轮追问变化 |
| 用户手动改名 | 对话顶部“重命名”打开小弹窗；保存后立即同步前后台，后续自动命名永久让位于手动标题 |
| 后续审批、执行、重试、交付 | 沿用同一显示标题；不因为任务进入不同状态而重命名 |

名称不能为空，去除首尾空白、合并换行 / 连续空白，最多 40 个可见字符（Unicode grapheme cluster，不截断 emoji）。输入超长时提示修改，禁止静默截断。按 Enter 保存、Escape / 取消不保存；关闭后焦点返回重命名按钮，未发送消息草稿不丢失。弹窗跨模拟回复重绘保留名称草稿；切换会话 / 身份或撤权时关闭并拒绝保存。只有当前有权编辑该会话的用户可改名，普通后台审阅或配置权限不带改名权。

自动标题只概括目标 / 现象，不把模型猜测写成已确认根因；不直接摘录账号、手机号、邮箱、URL、凭据、完整请求号、日志或附件名。手动标题同样经过可见性与敏感内容规则校验，拒绝时只提示修改，不把被拒绝内容另存日志。原型仅检查常见格式，不能作为生产脱敏保证；真实实现需统一服务端内容检查。标题在列表、搜索、通知及缓存中也是受权限控制的数据，不能因“只有标题”而越权展示。

原型在 `task-title.js` 使用固定词汇与本地规则演示自动概括，不调用模型、读取附件或证明通用语义理解。无法识别时保留待补充名称，用户可直接改名。正式自动命名可复用已有获权对话处理的标题候选；异步失败时保持现有名称，不阻塞消息保存或启动额外执行，不为名称重试整个问题任务。

改名只更新 title、titleRevision、titleSource 和标题审计，不修改用户消息、inputRevision、结果版本、固定计划、operationHash、审批、预算或 Binding；不得触发重新执行、撤销批准或取消用户验收。既有审批仍展示原问题和固定条件，当前标题只是定位入口，不构成批准依据。

离线验证见 [title-checks.cjs](../prototype/tests/title-checks.cjs)：自动概括、待补充细化、附件隐私、前后台同步、执行 / 审批 / 验收不变性、手动锁定、输入校验、取消 / 焦点、同名编号、旧修订拒绝、窄屏与撤权。
