# 开发顺序、验证与交付门槛

状态：排期依据，待用户评审和实施授权。当前只交付文档、类型草案及离线原型修补；以下业务代码和试验均未开始。

## 按一条纵向链路交付

| 阶段 | 应交付什么 | 退出条件 | 尚不能宣称什么 |
| --- | --- | --- | --- |
| D0 合同与依赖验证 | 用户确认技术方向；版本清单；Java/TS 可复算合同样例；目标 Provider 差距清单 | JDK/Boot/JDBC/SDK 兼容检查；12 方法与错误/状态映射可审核；身份和部署策略明确 | SDK 可用不等于业务链路可用 |
| D1 最小服务骨架 | Maven/React 工程、迁移、合成测试身份、授权门禁、日志、持久化 Provider 替身 | 空库启动/重启；跨用户拒绝；消息与命令幂等；并发预占和崩溃恢复通过 | 测试身份不等于真实登录，替身不等于 ACP/总控 |
| D2 完整服务闭环 | 一条固定流程；系统内环境/绑定；对话、审批、任务、结果、文件和管理记录 | 页面创建配置和成员后完成同一服务链路；真实上传解析与确定性计算；正文/下载逐项授权 | 用合成数据跑服务不是接入业务资源 |
| D3 两条受控后端 | 总控适配与 ACP Runner、代码和 MCP 网关、真实模型观察 | 逐项共同契约；总控路径先过，再关闭总控验证直连；预算/权限/隔离留真实证据 | 其中一路通过不能宣称两路均支持 |
| D4 获权测试环境试点 | 指定系统、数据集和资源范围；身份源；责任人；备份与运维手册 | 用户复算证据与文件并确认；故障演练不重复执行；恢复和接管经过责任人验收 | 不自动推广至生产、写入、多 Agent 调度 |

D1/D2 优先可运行纵向闭环。配置可先支持必要字段，管理仍用列表/表单；自由流程画布、全面知识库、任意 Skill 脚本、复杂多节点、受控写入延后。资源、模型和场景扩展沿现有接口增加配置与适配测试，不在业务 Controller 加型号判断。

## 开发任务拆分

1. **合同与结构**：创建三个 Maven 模块和前端工程；依赖锁定、迁移验证、OpenAPI/Schema/DTO 生成检查、领域模块依赖测试。先实现不可变引用、错误和时钟/ID 端口。
2. **身份与配置**：成员与角色、系统下环境、对象草稿/显式发布、Agent/模型/资源绑定、有效能力预览。预览和发布同规则；模拟发现只能在测试配置启用。
3. **对话与材料**：持久消息、标题独立 CAS、上传隔离和解析、上下文清单、无工具理解用途、SSE 断线恢复。记录采用输入修订，迟到回调不得覆盖新计划。
4. **执行与审批**：固定流程、唯一 Binding、排队准入、额度总分账、outbox/inbox、权限桥、停止与核查；并发/失联测试先于真实 Provider。
5. **结果与管理**：确定性计算、证据等级、产物导入、待验证/解决、接管包、任务/审批列表、正文租约和审计。
6. **适配与试点**：经授权取得实际版本与资源，按 D3/D4 验收。发现真实能力不足时反馈设计，不临时绕过门禁。

每个任务的合并条件是功能、失败路径、权限与迁移一起完成；不能先留“前端可见按钮”，再把服务端守卫留待补做。

## 测试重点

| 层次 | 必测场景 | 证据归属 |
| --- | --- | --- |
| 领域单元 | 输入修订、计划依赖、标题手动优先、权限交集、额度继承、状态非法边 | Java 规则测试；不依赖真实网络 |
| PostgreSQL 集成 | 同键竞争、唯一 Binding、两审批人 CAS、总分账原子预占、事件重复/乱序、时区跨日、发布与准入竞争 | 真 PostgreSQL，不能用 H2 代替锁/约束证明 |
| 故障注入 | outbox 前后/发送后崩溃、接纳回执丢失、租约过期、停止与完成交错、备份恢复 | 原执行 ID/命令键、数据库前后状态和外部夹具事实 |
| 服务授权 | 未开通零权限、跨用户/租户、流/历史/附件/下载独立授权、撤权与正文租约到期 | HTTP 集成测试，前端隐藏按钮不算 |
| UI 端到端 | 登录→选择→上传→追问→审批→执行→交付→验证；后台定位同一问题；刷新/切页/多标签不重复启动 | 正式前端连接本地服务；现有 195 项原型检查可作体验参考，不直接算服务通过 |
| Provider 共同契约 | 现有 CP01–CP22；追加本次用途、排队过期、跨连接额度、已知/未知用量组合 | 两后端各自实际版本、制品和资源身份；`not_run` 不改成 pass，直到真实执行 |
| 资源隔离 | Agent 不申请权限仍无法越权；本地目录链接逃逸；Git 凭据泄漏；MCP schema 漂移/恶意链接；附件解压及输出超限 | OS/网络/工具拒绝回执；模型自述不算 |
| 证据交付 | 区间/时区/币种/单位不一致，代码版本不符，延迟/截断，文件哈希错，CSV 公式注入，用户未解决 | 输入和计算可复算；不以语言流畅度作为正确性 |

新增排队场景必须区分两类：未开始执行因审批过期或相关依赖变化而阻断；已经合法开始的执行不因普通展示/背景编辑被重写。撤权属于独立立即阻断未来动作的策略，不享受旧快照豁免。

## 运行和运维初值（建议，非已测指标）

首批按单台主机、一个平台实例、一个 Runner 和有界并发设计。消息保存不等待模型；SSE 用心跳和有界缓冲，慢订阅者重取快照。数据库连接池、工作线程、Agent 并发分别限流，不随虚拟线程数量无限放大。

拟定起始值：页面分页 50/最大 100；上传单文件 20 MiB；解析 60 秒；单次发现 30 秒；SSE 心跳 15 秒。审批期限、模型任务时限、日志/文件保留期和资源调用上限按环境策略设置。这些只是压测输入，真实附件和执行需求验证后再发布，超时不意味着外部停止。

监控至少覆盖：最老 outbox 年龄、接纳未知数/持续时间、审批到期和未分派数、并发占用、未上报用量、产物导入失败、正文访问拒绝、资源撤权传播。健康检查区分服务存活、数据库就绪与某环境可执行，连接故障不把已接纳任务改为失败。

部署前验证 TLS/同源 Cookie/CSRF、会话撤销、秘密引用及轮换、隔离模板、数据保留和恢复。若使用邀请制本地账号，必须补密码哈希、登录限流、恢复和会话失效设计；不能以简易测试登录直接上线。企业 OIDC 则明确 issuer/subject 映射、成员开通和登出失效，不直接信任邮箱域名。

先做单实例服务的备份恢复，不为首批引入 Kubernetes、消息中间件或高可用承诺。发布数据库采用向前兼容迁移和可回退应用版本；破坏性迁移另行评审。恢复后暂停分派、核查未决外部执行再开放，不能盲目清空队列。

## 每次交付应包含

精确提交与依赖锁文件、迁移摘要、运行说明、所用身份/资源范围、测试输入与真实输出、失败/未运行项、已知限制和回退步骤。证据存储禁止真实 Token、客户正文及私密路径；公开仓库只保存经授权的合成或脱敏记录。
