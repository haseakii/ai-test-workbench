## 开发任务拆分

1. **合同与结构**：三个 Maven 模块和前端工程；依赖锁定、MySQL/Flyway 迁移验证、OpenAPI/Schema/DTO 生成检查、模块依赖测试。实现不可变引用、错误与时钟/ID 端口；统一 UUID/UTC/Decimal/JSON 映射。
2. **身份与配置**：成员角色、系统下环境、对象草稿/显式发布、Agent/模型/资源绑定、有效能力预览。预览与发布同规则；模拟发现只能在测试配置启用。
3. **对话与材料**：持久消息、标题独立 CAS、上传隔离解析、上下文清单、无工具理解用途、SSE 恢复。记录采用输入修订，迟到回调不得覆盖新计划。
4. **执行与审批**：固定流程、唯一 Binding、排队准入、额度总分账、outbox/inbox、权限桥、停止和核查；MySQL 并发与失联测试先于真实 Provider。
5. **结果与管理**：确定性计算、证据等级、产物导入、待验证/解决、接管包、任务/审批列表、正文租约和审计。
6. **适配与试点**：经授权取得实际版本与资源，按 D3/D4 验收；真实能力不足反馈设计，不临时绕过门禁。

每项合并条件包含功能、失败路径、权限与迁移；不能先交付可见按钮，再把服务端守卫留待补做。

## 运行和运维初值（建议，非已测指标）

首批按单台主机、一个平台实例、一个 Runner 和有界并发设计。消息保存不等待模型；SSE 用心跳和有界缓冲，慢订阅者重取快照。连接池、工作线程、Agent 并发分别限流，不随虚拟线程数量放大。

拟定起始值：分页 50/最大 100；上传单文件 20 MiB；解析 60 秒；单次发现 30 秒；SSE 心跳 15 秒。批准期限、任务时限、日志/文件保留期和资源调用上限按环境策略设置。这些只是压测输入，不是已测能力；超时不意味着外部已停止。

MySQL 数据库连接必须验证实际 database、InnoDB、严格 SQL mode、UTC 会话、READ COMMITTED；使用 binlog 时核验 ROW 和落盘策略。TLS、凭据与受控网络按部署环境配置，不为连通而默认关闭证书校验或使用 root。池中时区/隔离级别不得因一次特殊查询遗留到其他事务。

监控至少覆盖：最老 outbox 年龄、接纳未知数/持续时间、审批到期未分派、活跃槽、未上报用量、产物导入失败、正文拒绝、撤权传播，以及连接池等待、死锁和锁超时。区分服务存活、数据库就绪与环境可执行；连接故障不把已接纳任务改为失败。

部署前验证 TLS/同源 Cookie/CSRF、会话撤销、秘密轮换、隔离模板、数据保留和恢复。邀请制本地账号需密码哈希、登录限流、恢复与会话失效；企业 OIDC 明确 issuer/subject、成员开通和登出失效，不直接信任邮箱域名。

先做单实例备份恢复，不为首批增加 Kubernetes、消息中间件或高可用承诺。MySQL 迁移采用向前兼容和可回退应用版本，破坏性变更另审；原子 DDL 不代表整批迁移可回滚。恢复后暂停分派，核查未决外部执行再开放，不盲目清空队列。

## 简单搭建交付验收（D4-DEPLOY，用户首装待验收）

用户新增要求：**部署复杂度不能太高，要能够简单搭建。** 普通使用者按一份说明完成首装是正式交付条件。沿现有 Java/MySQL/内置前端收敛为一条主安装路线和单一操作入口；用户随后明确选择 **Windows 电脑**；这不代表选择 Docker Desktop 或授权创建安装资源。Windows 入口与发行目录/ZIP在仓库内准备，实际 Windows 首装仍待验收。后续用户明确要求继续项目，已授权在原合成环境内实现和验证不需额外权限的交付准备。

首装目标已确定为 Windows 电脑；具体 Windows 版本/架构、Java交付方式、推荐应用/用户私有目录的便携Java/MySQL主路线，已有授权实例仅兼容；Windows二进制来源/摘要、目标机器和执行范围仍待冻结，持久数据/备份位置及首次管理员身份方式。交付预构建前端和服务，不要求普通使用者安装 Node/Maven/Python、编译源码、逐项执行 SQL 或手工组织多个运行目录。真实身份和资源连接仍须另外获权，不能用测试身份冒充已完成首装登录。

建议验收基线为**普通首装必填不超过 3 个独立输入**；这是待目标环境确认后冻结的方案目标，不是用户指定的数字或当前实测结果。端口/目录等提供安全缺省，密码和已有依赖的连接参数逐项计数，不能把一大段 JSON 称为一项来隐藏复杂度。实际字段、准确数量和特例尚待确定；如超过预算，先收敛并复核方案，不自动增加另一套首装路线。

当前 D2 合成运行只有平台 JVM（含前端/替身）和 MySQL，**2 个常驻单元**；启用后续独立 ACP Runner 时为平台、MySQL、Runner **3 个运行角色**，由同一入口管理。短期 Agent 子进程按执行创建，不要求使用者手工常驻；总控是可选外部后端。本轮不合并安全边界，也不为首装再增加网关进程、队列、缓存或对象存储服务。

| 操作 | 可验证的交付标准 |
| --- | --- |
| 首次启动 | 在确认的干净目标环境，由未参与开发的测试人员按唯一主路线、填写预算内配置并使用单一入口完成；预检依赖版本、配置、端口和数据目录权限。获准的数据库/最小账号初始化与迁移由入口协调，无人工 SQL；界面和所选身份可用后才报告就绪 |

| 升级 | 同一入口先核对制品/版本兼容并备份，再以短期迁移身份执行向前迁移、检查目标版本与就绪；运行服务不持有迁移权限。失败返回非零及具体阶段，不误报就绪；按已声明的兼容范围恢复应用/数据，不假设 DDL 可回滚 |

| 备份/恢复 | 同一入口或其明确子操作覆盖平台/Runner 日志、文件和秘密引用，说明备份点、所需权限及恢复步骤；在获准隔离目标实际恢复，先冻结分派并核查未决执行，不因旧备份重放任务。RPO/RTO 在目标试点前另行确认 |

证据须记录目标环境、每个必填字段、人工命令数、常驻单元数、耗时、故障提示与重试/恢复结果。测试多账号、隔离实例和权限负例属于内部验证，不转嫁为用户逐项安装操作；自动化仍保持账号/进程最小权限，不以 root 运行应用或绕过 TLS/安全提示来换取易用性。完整用户首装仍未验收，合成环境的交付准备结果不证明普通使用者已经能够简单搭建；A01 空实例和远端 CI 的原授权状态不变。
