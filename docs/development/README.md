## 当前技术方向

**JDK 21 + Spring Boot 模块化单体 + MySQL 8.4 LTS / InnoDB + Spring JDBC / Flyway + React/TypeScript + 独立 Java 执行宿主。** Spring Boot 等精确版本仍按 D0 验证后冻结，本轮不借换库另行升级其他候选依赖。

首条业务链路仍是一个系统测试环境的报表差异排查：截图和表格、只读取证、确定性计算、结果文件与用户验证。配置能力可扩展，首批按需实现；无需先完成全部管理页面。

技术分层不增加用户操作：用户不选择 ACP 协议、MCP 工具或底层执行参数。后台先把能力绑定到环境和固定流程，用户仅能看到获准系统、环境、模型预设和可用检查。缺少能力时给出原因和下一步，不自动切换连接。

平台状态库、Runner 接纳日志、被排查系统的数据源和外部总控存储是不同对象。前两者按 MySQL 8.4 分库分账号管理；业务数据源不被要求迁移，外部总控仍不共享数据库。首版不承担平台双数据库方言或 MySQL 5.7 兼容。

本轮仍没有创建 Maven 工程、业务 API、数据库迁移或真实 Agent 进程；本文目录树和 SQL 片段均为规划。现有 `docs/prototype/` 是离线评审材料，不能直接迁为权限服务。

## 需要评审或验证的少量取舍

| 事项 | 当前方向 / 建议默认 | 影响 |
| --- | --- | --- |
| Java 与数据层 | JDK 21、Spring Boot 4.1.x 候选、MySQL 8.4 LTS / InnoDB、Spring JDBC | 数据库方向已确认；补丁、Connector/J、Flyway 及事务实现经 D0/D1 实测后冻结 |
| 首批身份 | 一个部署只启用一种真实登录源；优先复用可用企业 OIDC | 无身份源时，内部测试可选邀请制本地账号，不能把测试身份当正式登录 |
| 部署形态 | 首次本地合成验证；真实试点建议单台 Linux 主机、一个受控执行节点 | 支持 Windows 开发；本地代码目录必须在获准执行节点上 |
| 额度与记忆 | 默认平台轮次 / 并发约束；未知用量须显式接受；跨会话记忆关闭 | 需要内部硬限额的环境，在执行器证明能力前阻断 |
| 下一阶段 | 先评审修订，再明确授权合成数据的 D0/D1 实施 | 真实模型、Token、业务资源和部署仍按指定范围另行授权 |

身份源、主机、具体 Agent 和试点资源尚未确定，这些不妨碍评审架构，但会阻塞对应实机验收。数据库方向确认没有替用户批准这些条件。
