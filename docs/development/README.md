# 开发设计

> **状态：技术方案待整体评审；尚未创建业务工程或连接真实资源。** 平台数据库方向已确认为 MySQL 8.4 LTS / InnoDB；其他精确依赖版本和实现细节须经 D0 验证后冻结。

## 当前技术方向

**JDK 21 + Spring Boot 模块化单体 + MySQL 8.4 LTS / InnoDB + Spring JDBC / Flyway + React / TypeScript + 独立 Java Runner。**

- 平台业务服务拥有身份、会话、配置、审批、额度、证据和验收。
- Runner 负责受控 ACP Client、Agent 进程、接纳日志和协议事件；不复制总控的多 Agent 调度能力。
- 通过 ExecutionProvider 接入现有总控或受控 ACP 直连。两个后端共享平台资源治理，但不共享数据库。
- 平台业务库与 Runner 接纳日志使用独立 database、账号和迁移历史；被排查系统的数据源保持独立。
- 首版只支持 MySQL 8.4 平台方言，不承诺 PostgreSQL 双方言、MySQL 5.7 或 MariaDB 兼容。

## 必须保留的执行不变量

1. 出队后、首次后端接纳前重新核验审批期限、配置依赖、权限、额度和停止标记。
2. 额度总账、模型分项、并发槽、命令和 outbox 在同一平台事务内原子预占。
3. 任何外部提交结果未知时，以原幂等键查询或核查；不创建新键重放。
4. 每个执行单元只有一个执行拥有者；后端在运行中固定，换后端必须先证明旧动作安全关闭。
5. 审批绑定固定操作计划；实际资源服务再次校验授权。执行完成与用户确认解决分开。

| D0：合同与依赖验证 | 锁定 Java / Spring / MySQL / SDK 组合，核对跨语言合同和后端能力差距 | 构建、迁移、协议和序列化验证完成；能力缺口有明确处置 |

文档一致性与离线原型检查不是业务服务验收。MySQL 专项用例 MY01–MY14 尚未在真实 MySQL 8.4 上执行；Java 工程、迁移脚本、真实 Provider、资源隔离、预算结算和恢复演练也尚未验收。后续交付必须明确区分通过、失败和未运行项。
