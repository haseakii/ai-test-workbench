# Runner contract work in progress

`FailClosedAcpProvider` is an unregistered placeholder. Its default authority denies all calls; an injected test authority cannot enable execution. Every method returns a structured error without touching the journal, starting a process, emitting a receipt, or claiming verified capabilities. The stdio host is likewise disabled by default. These classes do not provide a production ACP path.

The current journal schema is a preliminary arbitration primitive. Its unique key `(tenant_id, idempotency_key)` and primary key `(tenant_id, binding_id)` do not implement the Provider contract namespace `(tenantId, providerId, nodeRunId, commandType, idempotencyKey)`. It also lacks durable accepted-at time, provider run ID, receipt ID, closure proof and process facts required for typed found/closed responses. Do not register it as a Provider or infer final nonacceptance from a missing row. Design a forward migration with conservative treatment of existing rows, distinct command namespaces and immutable receipts before implementing lookup/close results; do not edit the existing V1/V2 migration files.

Required integration evidence includes cross-tenant/subject and cross-provider/node-run key isolation; simultaneous start/close and same-key/same-or-different-spec races; lost commit and response recovery; immutable receipts on restart; old-row migration without replay; and real database/agent-process fencing at the resource boundary. Synthetic test authority and isolated stdio fixtures are not proof of actual authentication, operating-system isolation or a real ACP backend.

V3's unregistered `ScopedCommandJournal` records only an intent in the five-field namespace; it neither admits nor launches execution. It indexes SHA-256 digests of exact UTF-8 provider, command type and idempotency key, persists the full original byte strings in LONGBLOB columns, and checks each original value on a digest match. Different bytes with the same digest return a conflict; Unicode and whitespace are preserved without truncation. Invalid Unicode is rejected consistently with canonical JSON. Existing V1/V2 owners must be reconciled and their writer fenced before integration; V3 deliberately does not map them or prove final closure.

The public Id contract has no explicit size ceiling. Java memory/array limits, MySQL LONGBLOB capacity and server/client `max_allowed_packet` constrain actual storage; failure is surfaced, never reported as accepted or silently truncated. An end-to-end request byte budget and oversize error still need to be specified consistently across transports. These are unregistered development components: injected-digest collision, Unicode, whitespace and long-identifier protocol tests pass, while real MySQL V3 migration, concurrency, collision handling, and recovery are not yet verified.
